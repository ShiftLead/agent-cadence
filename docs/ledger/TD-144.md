## TD-144: The memory harvest has nowhere to send a lesson about working in a tool's team (ShiftLead's): let a tool declare where its lessons go

**Priority:** low
**Type:** feature
**Added:** 2026-10-26 (Paul, after the first memory harvest; drafted by session `memory-vs-cadence`)
**Status:** Open — **decided 2026-10-26 (Paul)**: an extension point in the one harvest, not a ShiftLead wrapper around it (a wrapper is a second harvest that drifts from the first). Design first: the declaration's shape and where it lives.
**Blocked by:** decision (Paul) — the design: the declaration's shape and where it lives (a tool's command, or a file it installs), agreed with ShiftLead's side (shiftlead TD-1029); a grinder builds once it is written and he says go
**Location:** `files/docs/procedures/memory-harvest.md` section 3 (the sort) and section 5 (where a promotion goes); `files/scripts/memory_harvest.py` (the inventory, which could report each repo's declared tools — not the agent tools `wanted()` already means); `files/docs/cadence.md` §7.13 (the harvest) and §9.18 (*a tool may keep a directory of its own in a layer repo … dev-cadence never reads it*); ShiftLead ADR 2026-10-25 *ShiftLead requires dev-cadence*, Decision 7 (the person's `shiftlead/` directory)

**Why:** the first harvest (TD-125, 2026-10-26) found lessons about working as a member of a ShiftLead team — claim before editing, a steer's default waits for its bound, message peers with `ao msg`, `--author @me` is not "my PRs" — in consumer-a and shiftlead. They are neither cadence rules nor Paul's preferences: they hold for every ShiftLead user, so their home is ShiftLead's own texts, and one only Paul wants belongs in his layer's `shiftlead/` directory (the ADR's Decision 7). The sort has neither destination, so the run filed them by hand (shiftlead TD-1026) and two went to `craft.md` meanwhile. Paul asked whether ShiftLead should wrap the harvest instead (2026-10-26); the answer was no — one procedure, which a tool feeds.

**Fix:** design, then build: (1) **a declaration** a tool ships saying, for its lessons, the upstream (e.g. *a ledger entry in ShiftLead/shiftlead*, or an issue for someone who does not own it) and the personal path within the layer repo (`shiftlead/briefs/`), plus how a repo shows it uses the tool (`.shiftlead.yml`). Where it lives is the design question: in the tool's package, read through a command the tool provides (`ao … --json`), or a file the tool installs where `memory_harvest.py` looks; never a key a tool writes into `cadence.toml` (§9.18: tools never rewrite it; its only exceptions are dev-cadence's own layer-follow and pin edits), and §9.18's *dev-cadence never reads a tool's directory* either stays true or changes on purpose. (2) **The sort gains one question**, after *Is it already said?*: *is it about working inside a tool this repo uses?* → that tool's destination; with no declaration, it is judged as now. (3) `inventory --json` reports each repo's declared tools; the procedure, §7.13 and a `cadence-changes.md` entry say it. Tests: a fixture tool declaration, a repo using it, a repo not.

**Done when** a lesson about a declared tool is sorted to that tool's destination in a fixture run, and ShiftLead's declaration exists (shiftlead TD-1029).

**Related:** TD-125 (archived: the harvest), TD-141 (the harvest's other first-run changes), TD-132 (archived: `--json` for a tool's directory); shiftlead TD-1026 (the lessons filed by hand), TD-1029 (ShiftLead's side).
