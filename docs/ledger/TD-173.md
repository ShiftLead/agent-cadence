## TD-173: Agents write ledger entries by hand, so every convention is one they can slip on: every ledger write goes through `ledger.py`, and the gate refuses an entry file the helper would not have written

**Priority:** medium
**Type:** feature
**Added:** 2026-10-28 (Paul, in shiftlead session `queue-deps`; drafted there, filed by session `ao-dev-cadence-dc-techlead`)
**Status:** Open — design agreed (Paul, 2026-10-29: "the TD-173 design is right, file the builds"); its builds are TD-197 (vendor ledgerboard v2.2, whose TD-005 defines the canonical form and writers, and `fmt`), TD-198 (`new`), TD-199 (`set`, `note`, `edit`), TD-200 (`archive`, `reopen`, `renumber`), TD-201 (the gate) and TD-202 (the rule). The split it waited on landed (TD-160).
**Taken by:** ao-dev-cadence-dc-techlead
**Location:** `files/scripts/ledger.py` (today's reads, `--split`, `--check --since`), `files/scripts/ledger_next_id.py`, `files/scripts/ledgerboard.py` (vendored from ShiftLead/ledgerboard: `entries()`, `parse_blocked()`, `entry_path()`, whose v2.2 defines the canonical form and the entry writers: ledgerboard#TD-005, plan `docs/plans/2026-10-29-ledger-writer-in-ledgerboard.md`), `files/scripts/check_cadence.py` (the `ledger` row), `files/docs/cadence.md` §2.4, §2.10, §2.12; ShiftLead's Add entry flow and `ao td`, which would call the helper instead of writing text (a shiftlead entry, filed from there)

**Why:** an entry's header is a set of conventions an agent writes by hand: the field order, one `**Name:** value` per line, ids before `decision (<who>)`, no written Pickable, a wait as a Blocked-by item and never prose, an archive as a move plus a Status edit. Each one has slipped: TD-160's blocker sat in its decision's pointer, so nothing saw shiftlead#TD-1143 land (TD-172); TD-151 and TD-154 waited in prose (TD-166); hand-written Pickable lines disagreed with the derived one (agentorc, TD-073). `--check` finds some of these after the fact, and each finding adds a rule agents have to remember. One rule, "never edit a ledger file; use `ledger.py`", leaves nothing to remember and moves the conventions into code.

**Fix:** design first. The shape agreed with Paul on 2026-10-28:
- **Commands that cover every routine write**, since any routine edit left out sends agents back to editing by hand: `new` (every header field as a flag; Why, Fix and Done when from a file or stdin; the id from the counter, absorbing `ao td next`, since renamed `ao td reserve`, TD-182); `set TD-n --field value`, which checks each value as it is written (ids exist here or in a roster repo, the decision last, a value outside a declared `Fields:` vocabulary refused, and a pointer that holds an id refused); `note TD-n "…"`, a dated Status line; `edit TD-n --section why|fix|done --from file`; `archive`, `reopen`, `renumber`.
- **Enforcement by form, not by author:** the gate's ledger row refuses an entry file that differs from the helper's own rendering of it (read, write back), and names the command to run. A valid hand edit already in canonical form passes; the person keeps hand edits and runs `ledger.py fmt` before pushing. Turned on under `--since`, so only entries a PR changes are held to it.
- **The rule:** cadence.md §2.12, agents never edit a ledger file directly.
- **`new` writes `Id take`** from the counter's take (TD-188, the ADR 2026-10-28 ledger id provenance); `fmt` never touches it.
- **Order:** after the split (TD-160); the commands, then the gate check, then the rule. The prose stays free text, each in its own slot.

**Done when** every routine ledger write in agent-cadence's cadence and procedures is a `ledger.py` command; the cadence check fails a PR whose changed entry file is not in canonical form, naming the command; cadence.md §2.12 says agents never edit a ledger file directly; and two sessions filing and editing entries in one day touch no file by hand.
