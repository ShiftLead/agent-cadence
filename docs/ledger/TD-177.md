## TD-177: The squash commit names who wrote a change but not who merged it, so a bad merge can't be traced from git: a `Merged-by:` trailer, beside the `Co-Authored-By:` ones it keeps

**Priority:** medium
**Type:** feature
**Added:** 2026-10-28 (Paul, in shiftlead session `queue-deps`; drafted there, filed by session `ao-dev-cadence-dc-techlead`)
**Taken by:** ao-dev-cadence-dc-techlead
**Status:** Open — design first
**Location:** `files/docs/procedures/cadence.md` step 5 ~79 (`gh pr merge <n> --squash`, `glab mr merge <n> --squash`); `files/docs/cadence.md` §4.2 (*The squash keeps who worked it*: no `--body`, because a written body drops the trailers), §4.9 (the `cadence-review:` evidence comment), §9.9 (the agent co-author hook, `AGENT_NAME`); `files/scripts/forge.py` (the GitHub and GitLab forges; no merge call today); `files/scripts/check_cadence.py` (the rows that decide a merge); `files/scripts/git-hooks/prepare-commit-msg`

**Why:** Paul wants this for audit and forensics: when a bad behaviour turns up, trace it from git to the session that did it, then fix that session's brief, rule or code. Authorship already traces: §9.9's hook writes `Co-Authored-By: <AGENT_NAME>` on every agent commit and §4.2's squash keeps it on main. The merge doesn't. The forge writes the squash commit, so its committer is `GitHub <noreply@github.com>`, and the one who pressed merge lives only in the forge's PR data, under the account that merged, which here is shared by sessions and the person. On 2026-10-28 dev-cadence #429 (TD-129's closing slice, held for Paul's merge under his §4.11 rule) read as merged by that account, and git couldn't say whether Paul or a session had merged it. A behaviour change merged by a session that should have waited is exactly the event this needs to catch, and today only that session's transcript could show it.

**Fix:** design first. The shape proposed on 2026-10-28:
- **One merge command** (`forge.py merge <n>`, or a step in `check_cadence.py`'s exit-0 path) that composes the squash body itself: the PR's commit messages as the forge would join them, then the trailer paragraph with every `Co-Authored-By:` from those commits, deduplicated, plus `Merged-by: <AGENT_NAME>`. It passes that body through each forge's own option: `gh pr merge --squash --subject … --body …`, `glab mr merge --squash --squash-message …`, and Bitbucket's merge `message` if it is ever a forge here. git reads trailers only from the last paragraph, so a test holds that every trailer lands there. (Today GitHub itself ends the squash body with a `---------` line and a `Co-authored-by:` paragraph of its own, as dev-cadence #429's 82f5c72 shows; the composed body has to keep those authors in its one trailer paragraph.) §4.2's ban on a written body becomes "the merge command writes it".
- **The same paragraph can carry** `Reviewed-by: <reviewer model> (<verdict>)`, from the §4.9 evidence comment the gate already read, and `Precheck: <sha>`, the head the gate passed. Then `git log` alone answers who wrote, reviewed, checked and merged each change.
- **The model, not only the session** (Paul, 2026-10-28: with on-prem models coming, the record should show a model that misbehaves): the merge writes `Merged-by: <AGENT_NAME> (<adapter>/<model>)`, the model read as shiftlead#TD-645's commit hook reads it (`AGENT_MODEL_FILE`'s first line, else `AGENT_MODEL`, ShiftLead design §4.2). Each agent commit's `Agent-Model:` trailer is shiftlead#TD-645's, built with this or first.
- **No `AGENT_NAME`** (a person's shell) writes `Merged-by: <git user.name>`. A merge from the forge's web UI writes no trailer, and its absence reads as *a person, in the forge UI*. That's accurate while Paul is the only one who merges there. Say so in §4.2.
- **Forge comments** aren't git and can't carry a trailer: a `cadence-review:` comment and every other comment a session posts end with its `AGENT_NAME`, so the forge record is signed too. (A forge account per agent is the only way the forge UI itself shows the actor. It's forge-specific and costs an account each; out of scope unless Paul asks.)
- **Out of scope:** git notes (no forge shows them, and one shared notes ref conflicts the way the one-file ledger did) and a local squash pushed to main (the pre-push hook and branch protection rightly block it).

**Done when** a session's merge through the cadence leaves a squash commit on main whose last paragraph holds its `Co-Authored-By:` and `Agent-Model:` trailers and `Merged-by: <AGENT_NAME> (<adapter>/<model>)` (on GitHub and GitLab, each under test); `git log --format='%(trailers:key=Merged-by)'` names the merger of every cadence merge since; cadence.md §4.2 and procedure step 5 name the command; and a web-UI merge's missing trailer is documented as the person's.

**Related:** shiftlead#TD-645 (the `Agent-Model:` commit trailer, Owner dev-cadence; part of shiftlead#TD-638, design §4.2 *And the model*).
