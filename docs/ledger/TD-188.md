## TD-188: A new entry's id provenance is a copied `Taken by` with an overloaded name: replace it with a formal `Id take` field naming the counter take

**Priority:** medium
**Type:** debt
**Added:** 2026-10-28 (Paul, session `td-breakout`: "go with C′")
**Owner:** grinder
**Kind:** build
**Status:** Open — designed: dev-cadence's private plan *2026-10-28-ledger-id-provenance* (ADR, option C′). Its rollout order and step-4 precondition are binding. **Go given by Paul 2026-10-28.**
**Location:** ShiftLead/ledgerboard `SPEC.md` and `ledgerboard.py` `CADENCE_FIELDS` (vendored here as `files/scripts/ledgerboard.py`); `files/scripts/ledger_next_id.py` (module docstring ~7, 39–52; `judge()` and its `id-taken-by` / `id-no-taken-by` / `id-branch` keys; a nonce→ids index over `read_takes()`, which already reads `take:`; `take()`, the `--claim` retry return ~460 and exit-2 text; a new `--show`; the stderr line; `--json`); `files/scripts/ledger.py` (`id_flags()`, the docstring ~56–63 listing the id keys); `files/scripts/check_cadence.py` (`ledger_ids_check()`); `files/docs/cadence.md` §2.10, §2.12; `files/docs/cadence-changes.md`; `tests/test_ledger_next_id.sh` (tests 17–18d), `tests/test_check_cadence.sh` (the Taken-by ledger-row cases); ShiftLead's `sessionorc/agent_ids.py` `taken_by_line()` and `ao td next`/`reserve` output, as a shiftlead entry

**Why:** the gate needs each new id to be traceable to the take that gave it to this work (ShiftLead/shiftlead#2370). The branch cannot identify the work: most takes say `main` (TD-145's Why; on 2026-10-28, 113 of ShiftLead's 173 takes). So TD-145 made each entry carry `**Taken by:** <by>`, a copy of the take's `by`. That field has four faults, and in a public repo a fifth: the `by` it copies is by default the Claude Code session's id, so every new entry publishes one (the seed dropped the ones it carried, 2026-10-28):
- its name reads as a work claim;
- its value is an unstable identity (session uuid, seat or email), so a hand-off makes it "wrong";
- ledgerboard's spec does not define it, so a ledger that declares `Fields:` (ShiftLead, 1,102 entries, none carrying it) refuses it;
- it lingers in the header after the merge, where nothing reads it.

TD-150 would have made it required, spreading all four. The ADR's reviews (Fable and Sonnet, 2026-10-28) rejected the alternative of judging by branch (its option D).

**Fix:** the ADR's Decision, in its rollout order:
1. **ledgerboard** defines `Id take`, the 32-hex `take:` nonce of the counter commit that gave the id, as a cadence field (minor release). Its spec text states the lifetime: judged only where its id is new, inert after the merge, never stripped by a tool, and never an assignment.
2. **dev-cadence vendors it.**
   - `ledger_next_id.py` prints `**Id take:** <nonce>` (and `id_take` in `--json`), including on the `--claim` retry return (`given[claim]["take"]`).
   - It gains `--show TD-N`, which prints the line for the caller's own take and refuses another's, naming its `by`. `--by` handles a deliberate hand-off.
   - A `--claim` of an id already handed out exits 2, naming the take's `by`, date and sha, never its nonce.
   - The gate judges `Id take` alone wherever it is present. Where it is absent, the gate accepts a matching `Taken by` and warns.
3. **A shiftlead entry:** its front end prints the `Id take` line, deployed on every roster machine. Its `taken_by` key stays, as information.
4. **The gate requires `Id take`,** once step 3 is live everywhere.
   - It fails a new id with no `Id take`, or whose nonce names no take of that id, naming both ids where it is another id's take. The failure names the take by `by`, date and short sha, never its nonce, and points at `--show`.
   - Any take of a doubly-given id counts.
   - `id-taken-by`, `id-no-taken-by` and `id-branch` retire, `Taken by` is no longer read, and new entries stop writing it.
   - §2.10 and a cadence-changes entry say so.
   - A consumer's pin bump to this step lists open PRs whose new entries carry only `Taken by`.

**Tests**, on fixture counters:
- a matching nonce passes;
- a missing one fails;
- a nonce of another id's take fails, naming both;
- a range take's nonce passes for each of its ids;
- either take of a doubly-given id passes;
- a hand-typed id fails as before;
- the failure text holds no nonce;
- `--show` prints the caller's own take and refuses another's;
- during the transition, a wrong `Id take` beside a matching `Taken by` fails.

**Done when** a PR adding an entry with no `Id take`, or with a nonce of a take that did not give its id, fails `ledger.py --check --since` and the `ledger` row (naming both ids for another id's take, and printing no nonce), in a ledger with and without a `Fields:` line; a session that lost its line recovers it with `--show`; a hand-off between sessions does not fail a correct PR; and no front end writes `Taken by`.
