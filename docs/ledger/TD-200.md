**Location:** `files/scripts/ledger.py` (`archive`, `reopen`, `renumber`, over ledgerboard's `edit_entry()`; `relink()`, `set_rank()`); `files/scripts/ledger_next_id.py` (`--claim`, for a renumber's new id); cadence.md §2.8 (archiving), §2.10 (renumbering)

**Why:** archiving is a `git mv` plus a Status edit, reopening is the reverse, and a renumber also rewrites every reference to the old id. Each is several hand steps that a session can half-finish: a file moved but its Status still Open, or a renumbered entry that its dependents still name by the old id.

**Fix:**
- `ledger.py archive TD-n --why "…" [--pr N] [--pointer "…"] [--as-is] [--superseded-by TD-n]` writes the archived form through `edit_entry()` (the PR number only as the forge returned it, §2.8 and TD-137), then `relink()`s for one more `../` and `git mv`s the file to `archive/`. ledgerboard v2.2's `archive-open-parts` refuses archiving a parent with an open part.
- `ledger.py reopen TD-n --why "…"` writes the reopened Status, `git mv`s the file back and `relink()`s one level up; the session follows with `edit fix`.
- `ledger.py renumber TD-old TD-new` claims the new id (`ledger_next_id.py --claim`), `git mv`s the file, rewrites `Blocked by` and `Part of` across this ledger (`rename_ref`), moves the id in the rank file (`set_rank()`), and lists references in prose and in other repos for the session to judge. It stops at an entry `canonical()` refuses, naming it, writing nothing.
- It validates the result with `ledger.py --check --since`'s own flag set (`L.check` with the roster resolver and the rank file, `archive_loss_flags`, the id flags) plus `prose_wait_flags`, and refuses the write, naming the problem, on every error the gate counts. `cross-repo` is printed as a note, never a refusal. Two refusals of its own, about the entry it writes: a cross-repo id this command introduces whose roster repo was read and has the id in neither file (`Roster.state`'s `missing`, which `Roster.resolve()` drops today; the message carries `state()`'s `why` and says to fetch there), and a wait written in prose.
- An entry `canonical()` refuses is refused with the gate's hand-fix message.
- All three commit nothing.
- Tests: archive, then reopen, then archive again (one `**Resolved:**` section); `relink()` on both moves; archiving a parent with an open part is refused; a renumber updates its dependents' fields and the rank file.

**Done when** archiving, reopening and renumbering an entry are each one command, and none of them can leave a dependent pointing at a moved or renamed id.

**Related:** TD-173.
