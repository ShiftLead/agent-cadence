## TD-200: `ledger.py archive`, `reopen` and `renumber`: move an entry, and rename one, as commands

**Priority:** medium
**Type:** feature
**Added:** 2026-10-29 (Paul, session `sl-tds`: "the TD-173 design is right, file the builds")
**Owner:** grinder
**Kind:** build
**Status:** Open
**Taken by:** b675de241e6c
**Blocked by:** TD-197
**Part of:** TD-173
**Location:** `files/scripts/ledger.py` (`archive`, `reopen`, `renumber`); `files/scripts/ledger_next_id.py` (`--claim`, for a renumber's new id); cadence.md §2 (archiving), §2.10 (renumbering)

**Why:** archiving is a `git mv` plus a Status edit, reopening is the reverse, and a renumber also rewrites every reference to the old id. Each is several hand steps that a session can half-finish: a file moved but its Status still Open, or a renumbered entry that its dependents still name by the old id.

**Fix:**
- `ledger.py archive TD-n --why "…" [--pr N]` sets the Status to `Resolved YYYY-MM-DD: <why>`, replaces **Fix** with `**Resolved:** YYYY-MM-DD (PR #n)` as cadence.md §2.8 says (a PR number only as the forge returned it, §2.8 and TD-137), gives each relative link one more `../` (§2.8), and moves the file to `archive/` with `git mv`. `--superseded-by TD-n` writes §2.8's `Superseded YYYY-MM-DD by TD-n` Status instead. For a v1 ledger it moves the section to the archive file. It refuses while an open entry is `Part of` it, naming the parts.
- `ledger.py reopen TD-n --why "…"` reverses that, with a dated Status line.
- `ledger.py renumber TD-old TD-new` claims the new id (`ledger_next_id.py --claim`), renames the entry, and rewrites `Blocked by` and `Part of` references to it across this ledger. It lists any other reference in tracked files for the session to judge, since prose is not its to rewrite.
- All three commit nothing.
- Tests: archive, then reopen, round-trips; archiving a parent with an open part is refused; a renumber updates its dependents' fields.

**Done when** archiving, reopening and renumbering an entry are each one command, and none of them can leave a dependent pointing at a moved or renamed id.

**Related:** TD-173.
