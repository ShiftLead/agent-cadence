## TD-201: The cadence check's ledger row fails a PR whose changed entry is not in canonical form, naming the command

**Location:** `files/scripts/check_cadence.py` (the `ledger` row); `files/scripts/ledger.py` (`--check --since`, which gains the canonical-form test); cadence.md §2.12, §4 (the check's rows)

**Why:** the commands only help if agents use them, and a rule they must remember is the problem TD-173 removes. Enforcing by form, not by who wrote the file, keeps the person's hand edits: a valid edit already in canonical form passes, and `fmt` makes one so. Under `--since` only the entries a PR changes are held to it, so the existing ledger needs no flag day.

**Fix:**
- `ledger.py --check --since <ref>` adds one error for each changed entry where `canonical(text) != text`, naming the entry and the command that fixes it (`ledger.py fmt TD-n`, or the `set`/`note`/`edit` that should have made the change). A refused `canonical()` is an error naming the hand fix.
- **Changed means file bytes:** an entry counts as changed when its file differs from the ref's, or is new (a file new in `archive/` included). Today `--since` compares header dicts (`check(old=)`), which would exempt a reordered field or a body edit. The file-bytes rule decides only this test; the field checks keep the header-dict comparison, so the first `fmt` PR is not judged on every standing field flag.
- The cadence check's `ledger` row reports it, as it reports `--check --since` today. An entry the PR did not touch is never judged.
- This lands only after the commands (TD-198, TD-199, TD-200), so every error it raises has a command to name.
- Tests: a hand edit out of canonical form fails, naming `fmt`; the same edit after `fmt` passes; an untouched non-canonical entry is not flagged; a body-only edit is judged.

**Done when** a PR that hand-edits an entry out of canonical form fails the cadence check's ledger row with the command to run, and one in canonical form passes.
