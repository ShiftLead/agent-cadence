## TD-204: Design reviews record their outcomes: exact models and tokens per review, an `Escaped from:` link on defects a design missed, and an on-demand `review-stats` that rebuilds the data and reruns the trial

**Priority:** medium
**Type:** feature
**Added:** 2026-10-30 (Paul, session `sl-tds`: "the review data seems like a great tool for optimizing our cadence … the real help is to be able to check against issues that arose after the designs")
**Owner:** designer
**Kind:** design-first
**Status:** Open. Filed for design; held for the rounds and Paul's go (§2.4 layer rule), and after TD-203, whose findings table it extends.
**Taken by:** b675de241e6c
**Blocked by:** TD-203, decision (Paul)
**Location:** the findings table TD-203 adds (ADR `docs/plans/2026-10-30-design-review-rounds.md`, rule 6); cadence.md §2 (a new ledger field) and §4.8; `files/scripts/cadence_config.py` (a key); a new `files/scripts/review_stats.py`; `docs/review-data/aggregate.py` and `trial_rules.py` (its first form); `files/docs/procedures/` (where a defect is filed)

**Ask:** Agree the shape below (what each review records, the `Escaped from:` field, the opt-in key, the backfill), then the design rounds run under the ADR's rules.

**Why:** the 2026-10-30 dataset (`docs/review-data/`, 97 designs) was mined by hand from design histories, ADRs and transcripts, and it could answer how long review loops run but not whether they work: no design recorded which findings were build-changing, the models were named loosely, and the link from a design to the defects it later let through was guessed from ledger citations, a lower bound that missed most of what a careful re-read found. The trial (`trial-rev18.md`) had to use proxies for all three. TD-203's findings table fixes the labels going forward; this entry adds the rest, so the data accumulates as a by-product and the caps can be tuned from evidence. As agents get stronger and tokens cheaper, the same data shows when late rounds start finding real problems again, which is when a repo should raise its caps.

**Fix (proposed; for the rounds):**
- **Each review records its model and cost:** the findings table (or a short review log beside it) gains, per review, the exact model id (`claude-sonnet-5-5`, `gemini/<model>`), its role (fact-check or design review), tokens, and the date. The session has both from the subagent's return; it costs a few cells.
- **`Escaped from: <plan, ADR or TD>`**, a ledger field on a defect entry that a design should have caught. The session filing a defect asks one question: did the design miss this, or the build? Only the former gets the field. It is the link the trial could only guess at.
- **`review-stats`** (`files/scripts/review_stats.py`), on demand: read every plan's findings table and every `Escaped from:` across the roster's repos, rebuild the dataset locally (beside the roster, never committed), and rerun the trial against the repo's current caps. Publishing a scrubbed copy, as `docs/review-data/` was, stays a deliberate separate step.
- **An opt-in key**, `review-outcomes` (default `off`): turns on the `Escaped from:` question at filing and a periodic reminder to run `review-stats`. The per-review cells are recorded either way, since data not recorded at the time cannot be filled in later.
- **Backfill:** a repo that turns the key on later can run a backfill pass: for each defect entry since a date, decide escaped-from or not and add the field. **This repo's own backfill** comes with the build: the 97-design dataset already lists the post-build defects found (TD-947 → TD-960, TD-995 → TD-1128, TD-1051 → TD-1095, …); the fields go on ShiftLead's entries through a ShiftLead PR, on agent-cadence's directly, and dev-cadence's (archived) stay in the dataset only.
- **Later, not now:** a mode that suggests cap values from the data. With fewer than 100 designs and almost no build-changing labels it would fit noise.

**Done when** each review in a design round records its exact model, role and tokens; a defect a design missed can carry `Escaped from:`; `review-stats` rebuilds the dataset and reruns the trial from the repos alone; the key exists, default off; and this repo's backfill is done.
