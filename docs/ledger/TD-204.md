**Why:** the 2026-10-30 dataset (`docs/review-data/`, 97 designs) was mined by hand from design histories, ADRs and transcripts, and it could answer how long review loops run but not whether they work: only one design (TD-173's ledger writer) recorded which findings were build-changing, tokens were recovered for under half the reviews, the models were named loosely, and the link from a design to the defects it later let through was guessed from ledger citations, a lower bound that missed most of what a careful re-read found. The trial (`trial-rev18.md`) had to use proxies for the labels and could not test the link at all. TD-203's findings table fixes the labels going forward; this entry adds the rest, so the data accumulates as a by-product and the caps can be tuned from evidence. As agents get stronger and tokens cheaper, the same data shows when late rounds start finding real problems again, which is when a repo should raise its caps.

**Fix:** build 2 of the ADR's Design 6, as its rules 1–7 state: a design's review record is `docs/reviews/TD-NNN.md` (header, Reviews table, findings table); `Escaped from:` names the design TD a defect escaped from; the key `review-outcomes` (default off) turns on the filing question in `ledger_next_id.py` and the backfill suggestion; `review_stats.py` rebuilds the dataset from the roster's record files and ledgers, mechanically and statelessly, with `--candidates` for the backfill; and `docs/reviews/TD-203.md` copied from the rounds ADR's record. Vendor ledgerboard v2.2 here unless another build has. The fixes no review read (F84–F91: the seed template's line, the json output shape, `Roster` resolution and unmatched values, the TD-203 mapping, the frozen scripts run from a temporary copy, `escaped from` in v2.2) are fixed, not reviewed; the builder checks them.

**Done when** a design's record file carries each review's exact model, role and tokens; a defect a design missed can carry `Escaped from:` and passes `ledger.py --check --since` in a ledger with a `Fields:` line; `review-stats` rebuilds the dataset and reruns the trial from the repos alone; the key exists, default off; `docs/reviews/TD-203.md` exists; and a `cadence-changes.md` entry announces it.
