**Why:** two board writes have no writer anywhere: a new `decide` item, with its kind, `Answers:`, `(default)` mark and detail block, and the archive of closed items. A session types those by hand. In agent-cadence nothing writes a new item at all: `board_edit.py` makes only snooze, done, decide and reply. ShiftLead's `board.py` adds plain and already-decided items through ledgerboard's `item_line()` and `decided_line()`, which take no kind or `Answers:`. Every hand-typed convention (one line per item, the field order, a `Due:` before the trailing fields, a reply's place) is one an agent can slip on. TD-173 settled this for the ledger: one rule, "never edit a ledger file; use `ledger.py`", with a gate that refuses an entry file the helper would not have written, leaves nothing to remember. The board needs the same, and Paul set the scope on 2026-10-30: every repo that uses ledgerboard writes its ledger and its board only through the helpers, never by hand.

**Ask:** answered 2026-10-30 — Paul's go ahead (board), before the rounds: the design's review rounds still run once TD-202 and ledgerboard#TD-008 have landed, and no build is filed before they end.

**Fix:** the shape Paul agreed on 2026-10-30, rescoped 2026-11-02 by ledgerboard's target design (§1.1):
- **The writer is ledgerboard's `board.py`** (ledgerboard#TD-016, v2.3): `add` (any kind, with `Answers:`, a `(default)` and the detail block's named parts), `list`, `snooze`, `due`, `done`, `decide`, `reply`, `archive` (the closed items, once `ARCHIVE_AT` sit on the board) and `fmt` (every board's item lines into the canonical form, once, under the key rule). `board_edit.py` becomes the wrapper over those commands (TD-213), so ShiftLead's calls and the tool-made-edit carve-out (§4.5) keep working, with the same `--line`/`--expect` addressing and commit subjects.
- **The gate:** the cadence check's board row fails a PR whose added or changed item line ledgerboard's `item_problem()` names, saying which `board.py` command writes it. The detail block stays the person's prose and is not gated.
- **The rule**, in cadence.md §2.12 and §3 with a `cadence-changes.md` entry: in every repo that uses ledgerboard, a session never edits a ledger or board file by hand; it writes through `ledger.py` and `board.py`. This extends TD-202's ledger rule to the board and to every consuming repo. It covers tool code too (Paul, 2026-10-30: "ShiftLead's own board.py should call ledger.py and board.py. Any place in shiftlead that makes ledger or board edits should do so"): a consumer's code that edits a ledger or board goes through the writers, never ledgerboard's module functions directly, so the gate's test is the same for a person, a session and a tool. ShiftLead's part is shiftlead#TD-1286.

**Done when:** every routine board write in agent-cadence's cadence and procedures is a `board_edit.py` command over ledgerboard's `board.py`, the board row fails a hand-typed item line, every board on the roster has had its `fmt` pass, and cadence.md states the rule for both files.

**Related:** ledgerboard#TD-008 (the format half, v2.3); TD-173 and TD-197 to TD-202 (the ledger's helper, gate and rule, which this follows); `board_edit.py` and §4.5's tool-made-edit carve-out (dev-cadence TD-036); shiftlead#TD-1286 (ShiftLead's sessions and code onto the helpers).
