## TD-206: Agents type board lines by hand: every board write goes through `board.py`, and every repo that uses ledgerboard writes its ledger and board only through the helpers

**Priority:** medium
**Type:** feature
**Added:** 2026-10-30 (Paul, ledgerboard session `led-tds`: "Every repo that uses ledgerboard should only use the helpers (ledger.py, board.py) and never edit the ledger or board by hand")
**Status:** Open 2026-10-30: shape agreed in conversation (board.py with board_edit.py as its alias, the gate on the item line only, a fmt pass, after the ledger builds); design rounds not run
**Taken by:** 965518f644df
**Blocked by:** TD-202, ledgerboard#TD-008, decision (Paul) — the design's review rounds, then Paul's go
**Location:** `files/scripts/board.py` (new), `files/scripts/board_edit.py` (becomes its alias), `files/scripts/check_cadence.py` (the board row), `files/docs/cadence.md` §3.3–§3.5 and §2.12 (the rule), `files/docs/procedures/` (each step that types a board line), `files/docs/cadence-changes.md`; ShiftLead's `src/sessionorc/board.py`, as a shiftlead entry

**Why:** two board writes have no writer anywhere: a new `decide` item, with its kind, `Answers:`, `(default)` mark and detail block, and the archive of closed items. A session types those by hand. In agent-cadence nothing writes a new item at all: `board_edit.py` makes only snooze, done, decide and reply. ShiftLead's `board.py` adds plain and already-decided items through ledgerboard's `item_line()` and `decided_line()`, which take no kind or `Answers:`. Every hand-typed convention (one line per item, the field order, a `Due:` before the trailing fields, a reply's place) is one an agent can slip on. TD-173 settled this for the ledger: one rule, "never edit a ledger file; use `ledger.py`", with a gate that refuses an entry file the helper would not have written, leaves nothing to remember. The board needs the same, and Paul set the scope on 2026-10-30: every repo that uses ledgerboard writes its ledger and its board only through the helpers, never by hand.

**Ask:** once TD-197 to TD-202 and ledgerboard#TD-008 have landed, run this design's review rounds and give the go?

**Fix:** the shape Paul agreed on 2026-10-30, for the rounds to settle:
- **`board.py`**, over ledgerboard's board writers (v2.3, ledgerboard#TD-008): `add` (any kind, with `Answers:`, a `(default)` and the detail block's named parts), `list`, `snooze`, `done`, `decide`, `reply`, `archive` (the closed items, once `ARCHIVE_AT` sit on the board) and `fmt` (every board's item lines into the canonical form, once). `board_edit.py` stays as an alias, so ShiftLead's calls and the tool-made-edit carve-out (§4.5) keep working, with the same `--line`/`--expect` addressing and commit subjects.
- **The gate:** the cadence check's board row fails a PR whose added or changed item line ledgerboard's `item_problem()` names, saying which `board.py` command writes it. The detail block stays the person's prose and is not gated.
- **The rule**, in cadence.md §2.12 and §3 with a `cadence-changes.md` entry: in every repo that uses ledgerboard, a session never edits a ledger or board file by hand; it writes through `ledger.py` and `board.py`. This extends TD-202's ledger rule to the board and to every consuming repo. For the rounds: ShiftLead's own code writes through ledgerboard's writers in process (`board.py`'s `item_line`, `decided_line` and `edit_line`, and its ledger path after TD-202); whether that counts as "the helpers" or must call `ledger.py`/`board.py` is a question for Paul in the rounds.

**Done when:** every routine board write in agent-cadence's cadence and procedures is a `board.py` command, the board row fails a hand-typed item line, every board on the roster has had its `fmt` pass, and cadence.md states the rule for both files.
