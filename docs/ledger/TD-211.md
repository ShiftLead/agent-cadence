## TD-211: A session's forge comments are unsigned, so the forge shows only the shared account: end each evidence comment with its AGENT_NAME and model

**Priority:** low
**Type:** feature
**Added:** 2026-10-31
**Owner:** grinder
**Kind:** build
**Status:** Open
**Taken by:** ao-agent-cadence-ac-grinder
**Location:** files/docs/cadence.md §4.9; files/docs/procedures/cadence.md step 3; tests/test_check_cadence.sh

**Why:** A forge comment can't carry a git trailer, so the forge's own record of which session posted a `cadence-review:` evidence comment, or any other, is the account that posted it. Sessions and the person share that account. TD-177's Fix proposed signing every comment a session posts with its `AGENT_NAME` (and model). Its design (ADR docs/plans/2026-10-31-merged-by-trailer.md, item 5) deferred that in round 3: the signature leaves a forge record, not a git trace, so it does not serve TD-177's Why (tracing a bad merge through git). It is still worth having for the forge-side trail.

**Fix:** Each comment the cadence procedure has a session post (the §4.9 evidence comment and its late form) ends with one line, `— <AGENT_NAME> (<adapter>/<model>)`, or `— <user.name>` from a person's shell, read as TD-177's design reads the model and name (§9.9). `REVIEW_RE` reads the verdict on any line and takes the last such line, so the signature, which carries no `cadence-review:`, changes no reader. Other comments are their brief's to sign (ShiftLead's).
