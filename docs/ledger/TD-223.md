## TD-223: Temp-dir leftovers outrun every cleaner: precheck worktrees still escape TD-210's fix, and check_tmp.py only warns

**Priority:** Medium
**Type:** debt

**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 363794cedd5646c48f9638272ca105ba
**Location:** files/scripts/precheck.py main() (the mkdtemp/worktree try/finally); files/scripts/check_tmp.py (--hook, --report); files/docs/cadence.md §3.9 (The shared temp filesystem); files/docs/cadence-changes.md; tests/test_precheck.sh; tests/test_check_tmp.sh

**Why:** The temp directory every session on a machine shares fills faster than anything empties it. On 2026-11-04 `check_tmp.py --hook` (cadence.md §3.9, *The shared temp filesystem*) warned at 89% of /tmp's 1,048,576 inodes; the only automatic cleaner is systemd-tmpfiles' 10-day age, and sessions fill a 1M-inode tmpfs in a few days. When it runs out, no session on the machine can start a command (seen 2026-10-26). Two things keep it filling:

- **precheck.py's clean worktrees still escape.** 37 `precheck-<PR>-<rand>` directories sat at /tmp's top level (118k inodes), 6 of them made after TD-210's SIGTERM/SIGHUP fix (2026-10-31, PR #59), on 2026-11-02 and 2026-11-04 — so some path still skips the cleanup. Candidates, none confirmed: a SIGKILL (a `timeout -k`, a stopped background task's process group); a crash before the `try`; a consumer running an older pinned copy from before PR #59 (`precheck-2921-*` is a shiftlead PR's); or the `finally` itself failing quietly — `git worktree remove --force` and `shutil.rmtree(tmp, ignore_errors=True)` both give up on a read-only directory a suite left behind (a Go module cache, a chmod'd fixture), and neither result is checked.
- **check_tmp.py only warns.** Past its threshold it names the largest directories and prints cleanups for the person (§3.9: "No session runs a cleanup: the files may be other sessions'"). The person then cleans by hand, every few days, files that are known leftovers of their own sessions.

Reported by the person's ledger session (ao-led-tds-ledger) on 2026-11-04; the counts above are its, from that day's /tmp. At filing (2026-11-04 evening) /tmp held two `precheck-*`, both from that day.

**Fix:** 1. **Find and close the precheck escape.** Reproduce each candidate in the Why against `tests/test_precheck.sh` (SIGKILL of the parent, a read-only directory in the worktree at cleanup); make the `finally` remove what it made even past a read-only directory (make it writable, then remove) and say so on stderr when it cannot. A SIGKILL cannot be caught, so also: at start, `precheck.py` reaps stale `precheck-*` directories in the temp dir that are its own user's and older than a day — `git worktree remove --force` where the clone still lists one (else `git worktree prune` on the clone), then the directory.
2. **check_tmp.py reaps the user's own known leftovers past its threshold**, instead of only telling the person: under the temp dir, `-mindepth 1` so the directory itself never matches, only entries owned by the running user, older than a day, matching known patterns (`tmp*`, `precheck-*`, `pytest-of-<user>/pytest-*`), making read-only directories writable first. It reports what it removed and what it freed; anything else stays as today's printed cleanups. This reverses §3.9's "No session runs a cleanup" for these patterns only — the person's call, made in the request (2026-11-04: "keep it to the user's own files and known patterns, and say so in cadence.md"). So: cadence.md §3.9 says what is reaped and why only those, `check_tmp.py`'s header ("Nothing is ever removed") changes with it, and a `files/docs/cadence-changes.md` entry records the convention change (§3).
3. Tests, offline and in a scratch temp dir: an aged `precheck-*`, `tmp*` and `pytest-of-<user>/pytest-*` are removed past the threshold, a fresh one and another user's are not, a read-only tree is removed, and nothing is touched below the threshold.

**Done when:** A precheck stopped by SIGKILL, or one whose worktree holds a read-only directory, leaves nothing a day later (the next precheck reaps it); and past its threshold `check_tmp.py` removes the user's own aged leftovers of the named patterns, reports what it freed, and touches nothing else.
