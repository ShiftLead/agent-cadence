## TD-227: A red cadence/precheck names no failing test: put the failures in the status description, ahead of the command

**Type:** feature
**Added:** 2026-11-04 (shiftlead's designer ao-shiftlead-designer-ao-1, carried by shiftlead's techlead ao-shiftlead-techlead-ao-1, through ao td add; drafted by ao-agent-cadence-ac-techlead)

**Location:** files/scripts/precheck.py main() (the `Popen` of the command, and the `desc` line); files/scripts/forge.py `set_status` (GitHub cuts the description at 140 characters, GitLab at 255); files/docs/cadence.md §4.12; tests/test_precheck.sh

**Why:** The `cadence/precheck` status is the merge gate's record (cadence.md §4.12). Its description is `<passed|exit N> in <s>s on <host>: <cmd>`. A red one says the command failed, not which test failed, so two red prechecks with different causes read the same. shiftlead's TD-1295 design (shiftlead#2931, open) logs each red `cadence/precheck` so that a gate on the host's log can wait on "this test fails again". With no test named, a red precheck on a PR (the sightings in shiftlead's TD-1218) matches no test. Two facts in the code shape the fix. First, `precheck.py` does not capture the command's output: it inherits stdout, so the names have to be read from a copy (a tee) and the terminal must still show everything. Second, the command comes last in the description, and `forge.py` cuts at the forge's limit. This repo's own `precheck` command is longer than 140 characters, so on GitHub anything put after the command is always cut off.

**Fix:** Asked for: on failure, put pytest's `FAILED` node ids (from its short test summary) after the exit code, cut to 140 characters with `…` when they do not fit. The payload is shared by every consumer, and not every consumer runs pytest. This repo's suite is `run_tests.sh`, which prints a `FAIL` line per suite. So the build reads both forms, pytest's `FAILED <nodeid>` and `run_tests.sh`'s failing suite names, and records nothing extra for any other output. It may also add an optional pattern in `docs/cadence.toml`, if the builder judges that worth having. Order: `exit N in <s>s on <host>: <failures>; <cmd>`. The failures come before the command, so the cut falls on the command. Cut at the forge's own limit, with `…`, inside `precheck.py` or `forge.py`, never by plain slicing. Tests, offline: a fake pytest summary and a fake `run_tests.sh` failure each reach the description, a long list is cut with `…` inside the limit, and a passing run's description is unchanged.

**Done when:** A failed precheck whose command prints pytest's short summary, or `run_tests.sh`'s FAIL lines, records a `cadence/precheck` description that names the failing tests ahead of the command, within the forge's limit; and a passing precheck's description is as before.
