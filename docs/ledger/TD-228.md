## TD-228: The gate sweep's forge reads are GitHub's only: a GitLab repo's event checks read as errors, and --apply opens no PR there

**Priority:** Low
**Type:** debt
**Added:** 2026-11-05
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** ed1a2cb3c230475fa113e373cb120440
**Part of:** TD-214
**Location:** files/scripts/forge.py (GitLab: repo_info, pr_state_of, ref_sha, file_at, includes, open_prs_files, pr_diff, create_pr); tests/test_forge_gitlab.sh

**Why:** The event runner (`event_checks.py`, TD-219) asks the forge for each check's facts, but only GitHub's reads are built. `forge.py`'s `repo_info`, `pr_state_of`, `ref_sha`, `file_at` and `includes` raise "not built yet" on GitLab. So a check whose repo is on GitLab always reads as an error, and the sweep files an "Event check broken" item for it. The same goes for the sweep's PR operations (`open_prs_files`, `pr_diff`, `create_pr`): `gate_sweep.py --apply` cannot open a lift or sweep PR in a GitLab repo. No consumer on this machine's roster carries an event gate yet, so nothing is broken today; a GitLab repo's first event gate is.

**Fix:** Build the eight reads in `forge.py`'s GitLab backend, against GitLab's REST API as the backend's other calls use it:
- `projects/:id` gives `visibility` and `default_branch`;
- `merge_requests/:iid` gives `state` (merged, closed or opened);
- `repository/commits/:ref` gives the sha;
- `repository/files/:path/raw?ref=` gives the file;
- `repository/merge_base` gives the ancestry;
- the MR list, the MR diff and MR create cover the PR operations.

Read each one's facts from a real project first, as docs/plans/2026-10-12-forge-adapter.md *GitLab, as read* did. Add fixtures to `tests/test_forge_gitlab.sh`.

**Done when:** `event_checks.py` gives the four outcomes for a GitLab repo's checks, and `gate_sweep.py --apply` opens its PRs on GitLab, each with offline fixtures.
