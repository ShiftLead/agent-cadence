**Why:** ledgerboard's `host-log` check (ledgerboard#TD-045, Paul's Go 2026-11-04 on revision 2 of ShiftLead/ledgerboard `docs/plans/TD-045-host-log.md`) lets an entry wait on an event only the host witnesses — a precheck failing again, a person's press, a session's message — as a gate, where today such a wait is a retired `**Waits:**` line that no reader holds on. The format half is ledgerboard's builds TD-047 and TD-048. The reader is agent-cadence's: the design's rule 13 (Paul's decision after its round 7) puts the file reading here, and ShiftLead runs it through its agent-cadence pin, so a `host-log` check means the same on every host. Until it exists, no host can answer a `host-log` gate, and such a gate waits silently.

The reader is security-sensitive: it opens files on the host, which may hold mail, presses and anything else written there, under a configuration a PR can change. Its opening, roots, visibility and limits rules (rules 10–11) are its whole job. ledgerboard's rounds 11 and 12 judged only the format (rules 1–7) and left rules 8–12 to be reviewed here, with the code (the design's *Open questions for the rounds*, F202).

agent-cadence has no list of paths only the person may change: the merge gate (`check_cadence.py`) has no such row, and `docs/cadence.toml` waits for the person only by §4.11's judgment. The design asks each consumer to treat `docs/ledger/log-sources.toml` as person-only (rule 11), so this entry has to build that check, not just add a path to it.

**Fix:** In series:
1. **The vendor PR** for the ledgerboard release that ships TD-048 (the next tag after B2 lands; ledgerboard files that release's entry), as the design's *What a consumer must do* (agent-cadence) gives it: `vendor_ledgerboard.sh` to that tag; `event_checks.Runner.run` branches on `host-log` before `self.target(c["repo"])` (a `host-log` check has no `repo`) and runs `hostlog.py check` per gate, mapping `none` to no outcome by leaving the gate out of `sweep()`'s results; `gates()` carries each entry's text so that branch can compute `gate_added()` and pass it as `--since` (without it `check` answers error, `since unknown`), with `--repo`, `--visibility`, `--host-config` and `--profiles`; the repo's `log-sources.toml` is piped to `--repo-config -` from the same tree `gate_sweep.py` read the ledger from (`git show origin/<default>:docs/ledger/log-sources.toml`, the working tree only where `tree_io` falls back to it); a non-zero exit, output that is not one JSON object, or no answer within a fixed 120 s is error, never no outcome; a gate whose answer is `none` is left out of the results `gate_sweep.plan()` hands `sweep()`, and `event_checks.results()` and `main`'s rows and exit code say no outcome for it rather than an outcome; `ledger.py` passes `today` to a `set` that can add a gate (today `_lb_plan` drops `today` from every command, so `set` gets none, and the new release refuses a gate-adding `set` without it); the merge gate runs `hostlog.py validate --ledger` on a PR that touches `docs/ledger/` or `log-sources.toml`, and treats a change to `docs/ledger/log-sources.toml` as one that waits for the person. With no host file, the runner gives no outcome.
2. **`hostlog.py`** to the design's rules 8–13 (the reader's half): the repo file `docs/ledger/log-sources.toml` and its checks (rule 8); the host file and resolution (rule 9); shapes, compression by content and reading (rule 10); roots, visibility and limits (rule 11); records (rule 12); and the CLI and exit contract (rule 13: `check` and `validate`, one JSON object and exit 0 for every outcome of `check`, `none` on a Python without `tomllib`). It imports the vendored module's `first_instant` and `count_host_log`. It is stdlib-only, run as `agent-cadence run hostlog.py`, and is added to `SYNC_FILES` and the README.md table. SPEC's *Host-log checks* (ledgerboard TD-048) is the contract it keeps.
3. **The reader's tests**, every case the design's *The fixture cases* lists under *The reader's tests* (shapes, compression, opening, lock-in, reading, resolution, roots, errors, the exit contract, limits, counting, validate), offline and built at run time in a scratch directory.
4. **The host-side warning** the design leaves to each consumer, "filed with its reader work" (*The builds*, on ledgerboard#TD-046): the sweep names, on this repo's board, a `host-log` gate no host has ever answered (a source only an unselected profile declares passes `validate --ledger` and is silent on every host). ledgerboard#TD-046 waits on it.
5. cadence.md §2.14 names the `host-log` check, the reader and the person-only file, with a `files/docs/cadence-changes.md` entry.

Review: as security-sensitive code, with rules 8–12 reviewed alongside the code (F202). The person-only path check is a new merge-gate rule every consumer will notice, so under §4.11 it waits for Paul at merge.

**Done when:** agent-cadence vendors the release that ships `host-log`; `hostlog.py check` and `validate` pass every reader case the design lists; the event runner answers a `host-log` gate through it; and the merge gate runs `validate --ledger` and holds `docs/ledger/log-sources.toml` for the person.
