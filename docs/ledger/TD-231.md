## TD-231: The cadence check hands the merge what it saw: `check_cadence.py --pr <n> --trailers FILE` writes the head, the reviews and the precheck it judged (TD-177 build 1)

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-05
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 66ab7564ddbd408d9e68006578beaede
**Part of:** TD-177
**Location:** files/scripts/check_cadence.py (row_review, check_pr, the CLI); tests/test_check_cadence.sh

**Why:** The merge can only write `Review:` and `Precheck:` trailers that say what the gate saw if the gate hands them over: today `check_cadence.py --pr <n>` prints rows and an exit code, and nothing a later command can read back, bound to the head it judged. This is the first build of TD-177's design (docs/plans/2026-10-31-merged-by-trailer.md, Design 1), which Paul said Go to on 2026-11-05 (board, the end-of-rounds item): without it `forge.py squash-message` (TD-232) has no gate file to compose from.

**Fix:** As the plan's Design 1 says, and its tests in Design 7 (`tests/test_check_cadence.sh`):
- `check_cadence.py --pr <n> --trailers FILE` (a usage error with `--branch` or `--since`): every run empties FILE first, then writes it whole (temp name, rename) — on exit 0 the verified form (`pr <n>`, `expect <sha>` from the PR's one read, one `Review: <model> (<verdict>)` per listed `cadence-review:` comment in posted order, `Precheck: <sha>` when the head's `cadence/precheck` status reads `success`); on another exit `pr`, `expect` and `unverified <exit> <failing row names|->`; on a run that could not read the PR, nothing.
- `row_review` and `check_pr` return what they read (each comment's model and verdict, the PR's `head_sha`); the review row gains `carve_out` (`board-edit`, `queue-edit` or none); `--trailers` writes from those fields, never from a rendered row. A model that is empty, `code` or `docs` is `unknown`.
- With no `--trailers` the check behaves as today.

**Done when:** `tests/test_check_cadence.sh` holds Design 7's `--trailers` cases (a pre-filled FILE emptied on a failing PR; lines and order on a passing PR with a BLOCK then a FIXED; `unknown` for a comment with no model; refused outside `--pr`; the unverified form; an unreadable PR leaves FILE empty; `carve_out` on a board-edit and a queue-edit PR), offline, and the suite is green.
