**Why:** A squash body written by the forge buries every `Agent-Model:` mid-body and names nobody as the merger, so git cannot trace a bad merge back to the session and model that made it (TD-177's Why). This is the composing half of TD-177's design (docs/plans/2026-10-31-merged-by-trailer.md, Designs 2 and 3), which Paul said Go to on 2026-11-05: a command that writes the squash subject and body ending in one trailer paragraph, while the merge itself stays a literal `gh pr merge` a merge guard still sees.

**Fix:** As the plan's Designs 2 and 3 say, with Design 7's `tests/test_forge.sh` cases and the parity test:
- `forge.py squash-message <n> --gate FILE --out DIR` writes `DIR/subject`, `DIR/body`, `DIR/sha` and merges nothing; it refuses no gate file, another PR's, one without `expect`, an `unverified` file without `--unverified "<why>"` (which writes one collapsed `Merge-override:` line), and `--unverified` on a verified file.
- `pr_commits(n)` for GitHub (`--paginate` through `_pages()`, compared with the PR's `commits` count) and GitLab (reversed; an unreadable page refuses); zero commits refuses.
- `squash_message(commits, trailers, …)`, the pure function: each commit's trailer paragraph as `git interpret-trailers --parse` finds it; `Co-Authored-By:` (deduplicated on email, case ignored, plus unlisted commit authors), `Agent-Model:` (distinct, first seen), `Review:`/`Precheck:` from the gate file, `Merge-override:`, then `Merged-by: <AGENT_NAME> (<model>)` — or `<user.name>` with no `AGENT_NAME`; a bad `AGENT_NAME`, or no name at all, refuses.
- The model and name read exactly as `git-hooks/prepare-commit-msg` reads them; the hook gains its `LC_ALL=C` window (a behaviour change: a non-ASCII model is now left out). cadence.md §9.9 states the reading once, §7.9's list gains the parity pair, and `cadence-changes.md` gets the hook's entry.
- Read before naming: `forge.py` already has a `pr_commits(pr: dict) -> int | None` in both the GitHub and the GitLab forge class (a count, read by their settings checks); the new method must not collide with either.

**Done when:** `tests/test_forge.sh` holds Design 7's `squash_message` and `squash-message` cases (gh/glab shims, no merge called), the parity test feeds one set of environments to the hook and `forge.py` and both write one model, a git round trip reads every key back through `%(trailers:key=…)`, and §9.9 and §7.9 name the pair.
