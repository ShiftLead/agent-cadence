**Why:** `Merged-by:` only catches the #429 event (a session merging what should have waited) if a merge without it is noticed: once everyone merges through step 5's line, a squash commit with no `Merged-by:` went around it. This is the detector half of TD-177's design (docs/plans/2026-10-31-merged-by-trailer.md, Design 4), which Paul said Go to on 2026-11-05.

**Fix:** As the plan's Design 4 says, with Design 7's `--since` cases:
- `check_cadence.py --since <window>` lists each merged PR whose squash commit carries no `Merged-by:` as *merged outside step 5*, a section after the rows and `merged_outside` in `--json` — a detector, never a fail.
- Cutoff: only merges after the repo's first squash commit with a non-empty `Merged-by:` trailer (`git log --format='%H%x00%(trailers:key=Merged-by,valueonly)'`, never `--grep`); a repo that never merged through the line lists nothing.
- A PR whose review row carries `carve_out` (TD-231) is listed apart as a tool merge; a merge commit this clone cannot read is counted *unreadable*, never listed.
- cadence.md §4.2 says what the list can and cannot tell (web UI vs. bare `gh pr merge` vs. an old pin; the cutoff's blind spot; an attested trailer).

**Done when:** `tests/test_check_cadence.sh` holds the cutoff (a commit that only mentions `Merged-by:` is ignored), a listed bypass after it, and the unlisted cases (with the trailer, before the cutoff, unreadable counted, a board-edit carve-out listed apart), offline; §4.2 says it.
