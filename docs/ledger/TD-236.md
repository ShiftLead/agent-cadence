## TD-236: The first merge through step 5's line reads its squash back: every composed trailer, `Merged-by:` last, nothing after (TD-177's live check)

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-05
**Owner:** grinder
**Kind:** live-check #147
**Status:** Open
**Id take:** 48fc50cb14944b0eb5a799d3c2d1442d
**Part of:** TD-177
**Location:** files/docs/procedures/cadence.md step 5; files/scripts/forge.py squash-message

**Why:** Until a merge has gone through step 5's line, what GitHub does with a given squash body is an assumption (TD-177's design 2, *What GitHub does with a given body*). §4.2 says that a written body drops GitHub's own `Co-authored-by:` paragraph, which suggests GitHub appends nothing to it, but no merge here has shown it. If GitHub writes anything after the composed trailer paragraph, `Merged-by:` is no longer in the message's last paragraph. git would then not read it as a trailer, and `check_cadence.py --since` (TD-234) would list every cadence merge as made around the line. #147 (TD-233) was the last merge made the old way.

**Fix:** After #147 merges, read the squash commit of the first PR merged through step 5's line: `git log -1 --format='%(trailers)' <its merge commit>` and `git log -1 --format=%B`. Every composed key should come back, `Merged-by:` last, with nothing after the paragraph. If anything follows it, file a defect entry (carrying `Escaped from: TD-177` if its filer judges it a design miss, cadence.md §2.13), block this check on it, and stop using the line until it is fixed.

**Done when:** The first squash commit merged through step 5's line reads back, through `%(trailers)`, every key `forge.py squash-message` composed for it, with `Merged-by:` last and nothing after the trailer paragraph. What was read is written on this entry.
