## TD-237: A tool's board append landed by a PR of its own fails the review row: §4.4 has no PR form, so check_cadence.py passes it as board-append only as a direct commit

**Priority:** medium
**Type:** debt
**Added:** 2026-11-05 (shiftlead's TD-1412 design, ao-shiftlead-designer-ao-1, through ao td add; drafted by ao-agent-cadence-ac-techlead)
**Status:** Open
**Id take:** 4b5b735db4dc4213a4cb10810971ec53
**Location:** files/scripts/check_cadence.py (row_board_edit_pr ~2475, board_edit_or_review ~2540, classify_direct ~2100, the module docstring's review row and --since sections); files/docs/cadence.md §4.4, §4.6; files/docs/cadence-changes.md; tests/test_check_cadence.sh

**Why:** §4.4 lets a service account push a board append straight to main, and the direct-commit audit passes it as **board-append**. A repo whose ruleset refuses direct pushes (§4.7) cannot use that route, so the append lands as a PR of its own. §4 gives that PR route to board edits (§4.5, TD-083) but has no PR form of §4.4. In `files/scripts/check_cadence.py`, `row_board_edit_pr` (~2475) returns None unless the title's `subject_kind` is `edit` or `archive`, so a tool's append PR goes to the ordinary review row. It fails `no cadence-review: comment` and, since TD-234, `--since` lists it as *merged outside step 5* rather than as a tool merge.

ShiftLead's `ao` writes its board appends this way. `src/sessionorc/board.py` `add` (*Put on the board*) and `add_decided` (the decided line a steer's or ask's answer writes) run ledgerboard's `plan_add` in the home's own tree, commit under ledgerboard's `append` subject, and land by `gh pr create` then `gh pr merge --squash`. shiftlead #2967 (merged 2026-11-05: title `shiftlead: append An entry that waits on … (session n/a)`, one commit, `docs/user_attention.md` +1 alone, a decided line) reads `FAIL review — no cadence-review: comment`. shiftlead's main took 12 such appends in the 7 days to 2026-11-05 (the asker's count). Every one is a false fail in the weekly sweep, and it buries the real bypasses that the merged-outside list exists to show.

The content is no looser than what §4.4 already passes unreviewed. Checked 2026-11-05: `classify_direct` run against shiftlead's squash of #2967 (4f98198df) returns `board-append`, so the decided line's form (`- [ ] decide … Due: … Decided: …`) already passes the direct audit's rules. Only the PR route lacks a carve-out. Asked for by shiftlead's TD-1412 design (ao's own merges are tool merges or go through step 5's line).

**Fix:** 1. **`check_cadence.py`**: a PR carve-out for a tool-made append, beside `row_board_edit_pr` (or as its `append` branch) and tried in `board_edit_or_review`. It passes the review row with `carve_out: "board-append"` when all three hold: the title's `subject_kind` is `append` (ledgerboard's `APPEND_SUBJECT_RE`, and the legacy forms where they still apply), the PR's files are the board alone, and its one commit (`_tool_pr_commit`, the forge's commit count, TD-224) is classified `board-append` by `classify_direct`. Anything else takes ordinary review. `--since`'s merged-outside section then lists such a PR among the tool merges with no change of its own (it reads the review row's `carve_out`). Update the module docstring's review-row and carve-out text.
2. **`files/docs/cadence.md`**: §4.4 gains the PR form, worded as §4.5's *The tool lands it by a PR of its own* is (a tree of its own at `origin/<default>`, a PR titled with the commit's subject, squash-merged at once, §4.6 passes it). §4.6's audit names the append PR beside the edit PR. This is a convention change, so it needs a `files/docs/cadence-changes.md` entry (§3).
3. **Tests** (`tests/test_check_cadence.sh`, or wherever `row_board_edit_pr`'s cases live): an append PR passes as a tool merge in both forms, a *Put on the board* line and a decided line. Negatives that still take review: a second file in the PR, a removed line, an append outside `## Needs…`, and a title that is not the `append` subject.

The change reaches shiftlead on its next pin bump (`agent-cadence bump`).

**Done when:** A tool's append PR in either form (a *Put on the board* line, or a decided line) passes the review row as `carve_out: board-append`, and `--since` lists it among the tool merges, each with a test. A PR outside those rules still takes review. cadence.md §4.4/§4.6 and cadence-changes.md record it.
