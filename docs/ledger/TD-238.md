## TD-238: `_board_diff` drops a removed board line that starts with `--` (it reads as a `---` file header), so a deletion can hide inside a board-append

**Priority:** Low
**Type:** debt
**Added:** 2026-11-06
**Owner:** grinder
**Status:** Open
**Id take:** c55004bcc5d7448a814dc325e670faf5
**Location:** files/scripts/check_cadence.py _board_diff; tests/test_board_writers.sh

**Why:** `_board_diff` in `files/scripts/check_cadence.py` skips every diff line that starts with `---` or `+++`, which is meant for the file headers. A removed board line whose own text starts with `--` therefore renders as `---…` and is dropped from the removed list. Then `classify_direct` reads a commit that deletes such a line beside a plain append as `board-append`. Since TD-237, `row_board_edit_pr` passes the same commit by PR as `carve_out: board-append`. The same goes for an added line starting with `++`. Found by the Sonnet review of #151 (TD-237), which deleted a `---` rule line together with one append and got `board-append` on both routes. The direct audit has had the hole since its start. The impact is small today, because only a line of dashes or pluses can vanish unseen, but a carve-out that misreads what was removed is no longer the rule it claims to be (cadence.md §4.4: an append never edits or removes an existing line).

**Fix:** In `_board_diff`, skip `---`/`+++` only as the file headers, before the first `@@` hunk header. Inside a hunk, every `-`/`+` line is content. Add a test in `tests/test_board_writers.sh`: a commit that deletes a `---` line beside one append is `fail` by `classify_direct` and `none` by `row_board_edit_pr`. `row_queue_edit_pr` reads `_board_diff` too, so check that it keeps its cases.

**Done when:** A removed or added board line whose text starts with `--` or `++` is counted in `_board_diff`'s result, and the test above holds on both routes.
