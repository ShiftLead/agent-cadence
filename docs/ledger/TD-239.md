## TD-239: event_checks.py cannot name a host file: run alone it reads host-log.toml only from the machine-scope directory, so ShiftLead runs host-log gates itself

**Priority:** medium
**Type:** debt
**Added:** 2026-11-05 (shiftlead's TD-1388, ao-shiftlead-grinder-ao-2, through ao td add; drafted by ao-agent-cadence-ac-techlead)
**Status:** Open
**Id take:** 4f2cdde518c24cc8b08d312804c1607b
**Location:** files/scripts/event_checks.py (main ~245, Runner.__init__ ~93, Runner.host_log ~148, host_file ~231, the module docstring); tests/test_event_checks.sh; files/docs/cadence.md §2.14

**Why:** `event_checks.py` answers a `host-log` gate by running `hostlog.py check --host-config <file>` (TD-230). `Runner` already takes the file (`host_file=`, ~93; `host_log` uses `self.host_file or host_file()`, ~155), but `main()` builds `Runner(top, timeout=...)` with no way to pass it, so run alone the script reads only `host-log.toml` in the machine-scope directory (`host_file()`, ~231, cadence.md §9).

ShiftLead keeps its host file in its own store (`<SHIFTLEAD_HOME>/host-log.toml`, shiftlead's design §4.4 *The host file*). Its event runner therefore cannot call `event_checks.py --json` for host-log gates: it runs `hostlog.py` per gate itself and overrides `event_checks.py`'s host-log rows (shiftlead's TD-1388). That is a second copy of how a host-log gate is run (where the repo's `log-sources.toml` comes from, the `--repo` and `--visibility` it is given, how a bad answer reads as `error`), and it can drift from the one cadence.md §2.14 describes. A flag lets shiftlead call `event_checks.py --json --host-config <store>/host-log.toml` and drop its own runner. Asked for by shiftlead's grinder (ao-shiftlead-grinder-ao-2) for TD-1388.

**Fix:** 1. **`files/scripts/event_checks.py` `main()`**: add `--host-config PATH` (default: unset, which keeps `host_file()`), `os.path.expanduser`ed and passed as `Runner(top, timeout=a.timeout, host_file=Path(...))`. A named file that does not exist reads as `host_log`'s *no host file* already does: no outcome, with the path in `why`. Say it in the module docstring and in the `--help` text.
2. **`tests/test_event_checks.sh`**: a case that runs the CLI with `--host-config` at a fixture host file outside the machine-scope directory (with `AGENT_CADENCE_REG_DIR` pointing at an empty one), and shows the gate's `hostlog.py check` ran with that file (an outcome where the default would give none). Offline, dates derived from the run date (TD-24).
3. **`files/docs/cadence.md` §2.14**: where it says `event_checks.py` run alone reads the checkout's `log-sources.toml`, add that `--host-config` names a host file other than the machine-scope one. Not a convention change for consumers (an added option), so no `cadence-changes.md` entry is needed.

`gate_sweep.py` builds its own `Runner(top)` (~354, ~541) and is out of scope; a host that sweeps with a host file elsewhere is a separate entry if one is asked for. The change reaches shiftlead on its next pin bump (`agent-cadence bump`).

**Done when:** `event_checks.py --host-config P` runs each host-log gate's `hostlog.py check` with `--host-config P`, and a test in `tests/test_event_checks.sh` shows it; without the flag the machine-scope file is read as before.
