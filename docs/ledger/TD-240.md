## TD-240: The gate sweep and the precheck status sign with the machine's hostname in a public repo: a per-machine `host-alias`, falling back to `gate-sweep`

**Priority:** medium
**Type:** debt
**Added:** 2026-11-06 (Paul's session ao-led-tds-ledger, through ao td add; drafted by ao-agent-cadence-ac-techlead)
**Status:** Open
**Id take:** 8139e532a6b04d2788de69f600790193
**Location:** files/scripts/gate_sweep.py (`host_token()`); files/scripts/gate_sweep_timer.sh (the unit's `Environment=`); files/scripts/precheck.py (~393, the status description); files/scripts/cadence_config.py (machine keys); files/docs/cadence.md §2.14, §9; files/docs/cadence-changes.md; tests/

**Why:** Two tools write this machine's hostname into a public repo, and nothing in the docs or the config says how to stop them.

- **The gate sweep signs each lift with it.** `gate_sweep.py`'s `host_token()` uses `$CADENCE_HOST`, else `socket.gethostname()`'s first label. Nothing sets or documents `CADENCE_HOST`: not cadence.md §2.14, not `cadence_config.py`'s keys, and not the unit `gate_sweep_timer.sh --write` writes (it sets only `PATH`). On 2026-11-06 the sweep's first event lift (TD-221, PR #160) put `gate lifted: … — by <the hostname>` on its Log line. The hostname names the login and the VM type. Pushing the lift branch had already published it, so the PR was closed and redone by hand as `by gate-sweep` (#162). The sweep's next run did not reopen the closed lift and filed an act asking why (#161), as §2.14 says it does.
- **`precheck.py` puts it in every `cadence/precheck` status**: `passed in …s on <the full hostname>: …` (`precheck.py` ~393). This repo is public, so every PR's head commit shows that status.

The publish gate does not catch either one. `cadence_layer.py --publish-check` already flags this machine's name and its short name (~604; the asker's report that it lists only people is not right). But it reads the files of a PR's tree at precheck. The sweep's lift branch is pushed, and so public, before any precheck runs, and a commit status is not a file. TD-124 settled the same leak for the ledger-id counter's commits with the repo key `ledger-ids-host = "off"`. No key covers these two writers.

**Fix:** 1. **A machine alias.** Add a machine-scope key to `cadence_config.py`, `host-alias` (in `~/.config/agent-cadence/cadence.toml`, which never leaves the machine): the name this machine signs with. `gate_sweep.py`'s `host_token()` reads `$CADENCE_HOST`, then `host-alias`, then the fixed word `gate-sweep`, never the raw hostname. Optionally keep the hostname as a last fallback only where the repo's `ledger-ids-host` is not `off`, so a private repo signs as before. Decide that when building.
2. **The timer.** `gate_sweep_timer.sh --write` writes `Environment="CADENCE_HOST=<alias>"` into the unit when an alias is set. Without one it writes nothing, and step 1's fallback applies.
3. **The precheck status.** `precheck.py`'s description names the alias, or no host at all, by the same rule as step 1.
4. **The docs.** cadence.md §2.14 (the sweep's lift Log line) and §9's machine-scope keys name `host-alias` and the fallback. §2.14 already says a lift PR closed unmerged is never reopened. It should add that a hand lift (`ledger.py lift --by … --evidence …`, as in #162) is the way forward. Add a `files/docs/cadence-changes.md` entry: a person with a public cadence repo sets `host-alias`.
5. **Tests.** `host_token()` with no env and no alias returns `gate-sweep`. With the alias set it returns the alias. The timer's unit carries the line only when an alias is set. The precheck description has no hostname.

The publish check needs no change for this: it already flags the hostname in files.

**Done when:** With no `CADENCE_HOST` and no alias, neither a sweep lift's Log line nor a `cadence/precheck` status carries this machine's hostname. `host-alias` is documented, and the timer and tests carry it.

**Log:**
- 2026-11-06: the asker's correction (ao-led-tds-ledger): #160's precheck did fail its publish gate on the Log line's hostname, so the gate caught the lift before merge; the leak is that the branch was public from its push. So a sweep without an alias opens lift PRs that fail the gate they go into. Also: the precheck's publish gate runs under xargs, which may split the tree into batches, each printing its own 'gate:' line, so the output's last line can read clean while an earlier batch failed (the exit code is still right). Worth one summary line when building, or an entry of its own.
