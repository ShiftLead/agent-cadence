## TD-241: The publish gate runs under xargs, so a split file list prints a clean last line after a failed batch and calls a needed accept line stale

**Priority:** Low
**Type:** debt
**Added:** 2026-11-06
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** c5aa490be08048f491f3cf4ea721aaab
**Location:** files/scripts/cadence_layer.py (--publish-check, --accept); docs/cadence.toml (precheck); files/docs/cadence.md §9.18

**Why:** A public repo's precheck runs the publish gate as `git ls-files -z | xargs -0 python3 …/cadence_layer.py --publish-check --accept <file>` (this repo's `docs/cadence.toml`, and cadence.md §9.18's recipe for a public repo). xargs splits a file list longer than its command-line limit into batches and runs the check once per batch. Each run prints its own `gate:` summary, so the output's last line can read clean while an earlier batch failed (xargs still exits 123, so the precheck's verdict is right). And each run judges `--accept` against its own batch alone, so an accept line matched in one batch is reported by another as *matched nothing — drop it if it is stale*: a false note that invites deleting a line the gate needs.

Scope: in this repo `git ls-files` is about 167 KB against xargs' 2 MB limit (`xargs --show-limits`, 2026-11-06), so it runs as one batch today; a consumer with a larger tree, or a smaller limit, splits. Noted on TD-240 by Paul's session ao-led-tds-ledger (2026-11-06).

**Fix:** Give `cadence_layer.py --publish-check` a way to read the file list itself — `--files-from -` (NUL-separated, as `git ls-files -z` writes) or `--tracked` (it runs `git ls-files` in the repo) — so the check runs once over the whole tree, with one summary and one accept judgement. Change the recipe in cadence.md §9.18 and this repo's `docs/cadence.toml` to it, with a `files/docs/cadence-changes.md` entry for public consumers. A test: a list split in two batches no longer reports an accept line as stale.

**Done when:** The publish gate runs once over the whole tracked tree in the documented recipe, so its summary and its stale-accept notes speak for every file; a test shows a line matched by one part of the tree is not reported stale.
