## TD-242: The memory harvest stamps the person's layer file with the machine's hostname: use host-alias, else no host

**Priority:** Low
**Type:** debt
**Added:** 2026-11-06
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** db13d6f4678347a8a6d7bd007ec1e5b3
**Location:** files/scripts/memory_harvest.py (stamp_line, ~555); files/docs/cadence.md §7.13

**Why:** `memory_harvest.py` stamps the person's layer file with `Harvested: <date> (<host>, <n> repos)`, the host being `socket.gethostname()`'s first label (`memory_harvest.py` ~555, `stamp_line()` ~299; cadence.md §7.13's stamp). The layer is a file in a git repo the person owns, may make public, or shares for others to follow (cadence.md §9.18, TD-130), and every session start prints it, so the machine's name rides into every session's context and the layer's history. TD-240 stopped the gate sweep and the precheck status naming the machine and gave the person `host-alias` for the purpose; this writer still names it. The layer repo's own publish check flags the short name before it goes public, so nothing has leaked through it yet — but its history keeps every stamp. Found by #165's Sonnet review (TD-240).

**Fix:** Stamp with `cadence_config.host_name()` (`$CADENCE_HOST`, else `host-alias`), and with neither, a stamp with no host (`Harvested: <date> (<n> repos)`), never the hostname. Check the stamp's readers (`memory_harvest.py`'s own parse of the line, and §7.13's text) accept the hostless form, and say it in §7.13. A test: with no alias the stamp carries no host; with one it carries the alias.

**Done when:** A harvest's stamp names the machine's host-alias or no host, never the hostname, and a test shows it.
