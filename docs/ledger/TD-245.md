## TD-245: precheck.py re-runs on a new head whose tree is identical to one that already passed

**Priority:** medium
**Type:** debt
**Added:** 2026-11-06 (Paul, through his session ao-led-tds-ledger, from a trial review of ShiftLead seats' transcripts; drafted by ao-agent-cadence-ac-techlead)
**Status:** Open
**Id take:** eccf5528c1524b908b772b91192ecaa4
**Location:** files/scripts/precheck.py; files/docs/cadence.md §4.12; check_cadence.py row_ci

**Why:** The precheck runs again on every new head, even when the tree it tests has not changed. `precheck.py --pr <n>` records `cadence/precheck` on a commit (cadence.md §4.12, TD-117), and the `ci` row reads the status on the PR's head commit. A fix that changes no file the command reads, like a rebase with an identical tree, or a ledger `fmt` that a narrower `[precheck-paths]` command would not cover (TD-155), still needs a full new run. That is about 12 minutes on ShiftLead.

This is the second half of the cost TD-244 names: TD-244 stops the cheap fails from coming after the precheck, and this stops an identical tree from paying for it twice. Seen in the same trial review (ShiftLead seats, 2026-11-03 to 2026-11-06), where a head moved by a fix that touched only docs or the ledger re-ran the whole precheck.

**Fix:** A proposal: before running, `precheck.py` looks for a passing `cadence/precheck` it recorded on an earlier commit of the same PR whose tree (`git rev-parse <sha>^{tree}`) equals the head's tree, run with the same command (the status's description names it). If it finds one, it records the head as passing, citing that commit, and does not run the command. The tree must be identical, not just similar: a reuse across any change in the tree is the trap. Then check whether `[precheck-paths]` (TD-155) already covers the ledger-only and docs-only heads on ShiftLead, and widen it in ShiftLead's own `docs/cadence.toml` if not (ShiftLead's, not this repo's).

**Done when:** A PR head whose tree equals an earlier head's that passed is recorded passing without rerunning the command, and the status says which commit it reused. A test holds that a one-byte change to the tree runs the command.
