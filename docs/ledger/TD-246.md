## TD-246: ledger.py set --blocked-by refuses <repo>#TD-n while that id is in an open upstream PR, so seats write a prose Waits: line instead

**Priority:** low
**Type:** debt
**Added:** 2026-11-06 (Paul, through his session ao-led-tds-ledger, from a trial review of ShiftLead seats' transcripts; drafted by ao-agent-cadence-ac-techlead)
**Status:** Open
**Id take:** eccf5528c1524b908b772b91192ecaa4
**Location:** files/scripts/ledger.py (Roster.state, xrepo_refused, set); files/scripts/forge.py in-flight; files/docs/cadence.md §2.4, §2.14

**Why:** `ledger.py set TD-n --blocked-by "<repo>#TD-m"` refuses while TD-m is still in an open PR in that repo. The resolver reads the other repo's ledger at its `origin/<default>` (`files/scripts/ledger.py` `Roster.state()`, around line 405). An id that is in neither the ledger nor the archive there is marked missing ("<repo> has no TD-m in its ledger or archive"). `xrepo_refused()` (around line 1005, TD-153) then refuses the write and suggests a fetch. The `cross-repo` flag the same id raises is only a note (`_introduced()`): the refusal is `xrepo_refused()`'s alone. That is common: one seat files an entry in another repo by PR, and another seat's entry waits on it.

Seen in the same trial review (ShiftLead seats, 2026-11-03 to 2026-11-06): 5 times, in two seats. Each time the seat wrote a prose `Waits:` line instead. That field is retired (cadence.md §2.12) and is the kind of prose wait TD-166 flags. Then the seat must remember to convert it to `Blocked by` once the upstream PR merges. A wait the tools cannot read is a block nobody lifts and nobody checks.

**Fix:** A proposal, in `xrepo_refused()`: when the id is missing at `origin/<default>` but an open PR in that repo adds it (`forge.py in-flight TD-m`, run in that clone, cadence.md §2.9), accept the block as pending on that PR. Write it as usual and print an ℹ note naming the PR. The block holds, since a missing id never lifts. The gate sweep (§2.14) or `--check` checks it again, and flags it as an error if the PR closes unmerged. An id that no PR carries still refuses, as now. Think about the forge call: it is a network read, so it needs a bound and an answer for an unreadable forge (refuse, as now).

**Done when:** `ledger.py set TD-n --blocked-by "<repo>#TD-m"` succeeds while TD-m sits in an open PR in that repo, with a note naming the PR. An id no PR carries is still refused. A closed-unmerged PR's id is flagged by the check.
