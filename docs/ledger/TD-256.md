**Priority:** high
**Type:** debt
**Added:** 2026-11-11
**Status:** Open
**Id take:** 412e1faf32654a08ae25a58f7feafa3e

**Why:** ledgerboard v2.7 is tagged (Paul's release, 2026-11-11; ShiftLead/ledgerboard#233), and ledgerboard's target design §7.2 step 6 (*Order of moves*) has both consumers (agent-cadence and ShiftLead) vendor it with `migrate` before any roster repo moves. Each roster repo's remodel is one PR that bumps its agent-cadence pin to the v2.7 release, so every roster repo waits on this vendor reaching main.

What v2.7 changes that this repo meets (ledgerboard `SPEC.md`, its v2.7 paragraphs and *Migrating to v2.7*): the Status set is closed (`Open` in the ledger; `Resolved <date>`, `Superseded <date> by <id>` or `Dropped <date>` in the archive), and any other Status word is an error that `migrate` maps, lists or stops on; a new `Waits` line is an error; `Location` becomes a body section; the sweep stops re-asking a lifting answer that was closed with no lift; `board.py decide --board-only` leaves a shared item unanswered and reports it as `left_open`, and the new `tripwire-shared-decided` holds that; a doubled `Recommended` label is refused; a refusal names the field it matched. This ledger does not pass the closed set today: seven live entries carry a Status that is not exactly `Open`: TD-065, TD-187 and TD-194 open with another word, and TD-144, TD-151, TD-156 and TD-182 add text after it (`Open — …`). So vendoring without `migrate` turns the `ledger` row of the cadence check red on every PR.

The `set by=` route (`files/scripts/ledger.py`, the lift in `set`, ~1440–1497) is this repo's wrapper over ledgerboard's board half: it calls `board.py`'s `plan_edit(board, "decide", …, board_only=True)` and, on success, prints the board path as written. ledgerboard's TD-067 plan (`docs/plans/TD-067-shared-part-lift.md`, *Consumers*) asks each consumer's vendor PR to check that a board half which writes nothing (`paths: []`, `subject: null`, exit 0, `left_open`) is taken as a success, the commit carrying the ledger alone under the `ledger: set TD-n …` subject, and that `left_open` is shown to whoever ran it. Today the wrapper would print a board path it did not write.

Asked for by a session of Paul's in ShiftLead/ledgerboard (ao-led-tds-ledger, by `ask`).
