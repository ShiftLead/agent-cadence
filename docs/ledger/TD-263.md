## TD-263: Vendor ledgerboard v3.0: migrate the ledger first, then split the board into a directory

**Priority:** high
**Type:** debt
**Added:** 2026-11-14
**Status:** Open
**Id take:** eae6bfe4f8b146a1b205fe5c044aad58

**Why:** ledgerboard v3.0 is tagged (Paul's release, 2026-11-14; ShiftLead/ledgerboard Release PR #327, tag `v3.0`). This repo vendors v2.8 (`files/scripts/ledgerboard/`, TD-259), and ShiftLead's own vendor follows this one: ledgerboard's plans put agent-cadence first, then ShiftLead (TD-098's plan, D12 and *Consumers*). Until this lands, every v3.0 behaviour waits, in both repos.

v3.0 changes two things this repo meets:
- **The ledger's old forms are gone** (ledgerboard TD-078): `Waits`, `Taken by`, the old decision form and a header `Resolved` are retired errors, and `migrate` is removed. So the ledger must be clean *before* the vendor, with v2.8 still in hand. TD-078's plan D5 states the precondition: run with the last v2.x, `ledger.py migrate --plan --release 2.8` prints no entry holding `changes` or `stops`, and the vendor PR records that output before vendoring. On 2026-11-14 it showed two, TD-262 and the archived TD-260, each `Added comment → Log`; the PR that filed this entry migrated both.
- **The board becomes a directory of item files** (ledgerboard TD-070, its migration TD-098). `docs/user_attention.md` is split with `board.py split` in the same vendor PR, and every script here that reads the board as text or by line moves to the `Board` that `load_board()` gives. TD-098's plan, section *Consumers*, lists agent-cadence's lines one by one (`board_edit.py`, `check_cadence.py`'s board rows and carve-outs, `nudge_user_attention.py`, `list_sessions.py`, `gate_sweep.py`, `ledger.py`'s `BOARD_REL`, `tests/test_parity.sh`, and more), with the grep and the before/after reader runs that prove it.

Asked for by a session of Paul's in ShiftLead/ledgerboard (ao-led-tds-ledger, by `ask`, 2026-11-14, m-5af1d1c51e0d).

**Location:** vendor_ledgerboard.sh; files/scripts/ledgerboard/ (vendored, v2.8 today); docs/ledger/, docs/ledger/archive/; docs/user_attention.md; files/scripts/board_edit.py; files/scripts/check_cadence.py (board rows, carve-outs); files/scripts/nudge_user_attention.py; files/scripts/list_sessions.py; files/scripts/gate_sweep.py; files/scripts/ledger.py; files/scripts/cadence_hooks.sh; tests/test_parity.sh; sync.sh and README's table; files/docs/cadence.md §3.3–§3.5; files/docs/cadence-changes.md; docs/briefs/techlead-context.md; ledgerboard docs/plans/TD-078-v3-ledger-half.md D5, TD-070-board-directory.md D12, TD-098-board-migration-release.md Consumers

**Fix:** One PR, in this order (TD-078's plan D5; TD-098's plan D12 step 1 and *Consumers*, the **agent-cadence** lines):

1. **The ledger precondition, with v2.8 still vendored.** Run `python3 files/scripts/ledger.py migrate --plan --release 2.8` and paste its output in the PR: no entry with `changes` or `stops`. If one appears, run `migrate` for it first, in this PR, and paste the clean run after.
2. **Vendor v3.0** with `vendor_ledgerboard.sh` (the stamp on `__init__.py`'s first line reads `v3.0`). Remove every call of `migrate` here; edit `sync.sh` and README's table if v3.0 adds or drops a file.
3. **Split the board** with `board.py split` in the same PR, when no open PR edits `docs/user_attention.md` (close a notices PR first and refile it after, TD-098's plan D11) and no unpushed board commit is held.
4. **Move every board reader** to `load_board()`'s `Board` and item ids, as TD-098's *Consumers* lists. First run its grep at this PR's base, and take each hit it finds that the list does not name by the same rule.
5. Update `files/docs/cadence.md` §3.3–§3.5 where they describe the board as one file, add a `files/docs/cadence-changes.md` entry, and update `docs/briefs/techlead-context.md` (the board's path).

**Done when:** `files/scripts/ledgerboard/__init__.py`'s stamp reads `v3.0`; the PR shows v2.8's `migrate --plan --release 2.8` run clean before the vendor; `docs/user_attention.md` is a directory of item files; TD-098's *Consumers* grep finds no name v3.0 removes outside the vendored module, and the reader runs it lists (`nudge_user_attention.py` daily and `--report`, `list_sessions.py`, the cadence check's board row) print the same items before and after the split. After the merge, the merging session records on this entry `gate_sweep.py`'s dry run and `--report --fetch` reading *matches*; the entry archives only then.
