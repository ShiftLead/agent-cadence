## TD-265: The ledger writer here cannot retitle an entry or remove a section, though ledgerboard's can

**Priority:** high
**Type:** debt
**Added:** 2026-11-14
**Status:** Open
**Id take:** cd04b6d1a18b449690ea858fed2904f0

**Why:** ledgerboard v2.8 added two edits to its ledger writer: a retitle (`set TD-n --title T`) and section removal (`edit TD-n --section NAME --remove`). Its TD-068 lists agent-cadence's wrapper as a consumer that should expose them. This repo's `files/scripts/ledger.py` lists `set`'s and `edit`'s flags by hand (`edit()` ~1219–1240). It has no `--title` for `set`, and `edit` refuses an empty section ("a section is never emptied by edit") with no `--remove`. So neither edit can be reached here, although the vendored module has had both since v2.8 (`files/scripts/ledgerboard/ledger.py:15`, `:24`; `plan_set(…, title=…)` ~538).

ShiftLead has no ledger wrapper of its own and runs this one, so the gap is in both repos. ShiftLead's grinder found it in the sync PR for ShiftLead TD-1803.

What it costs here, 2026-11-14:
- A retitle is a hand edit, which cadence.md §2.12 allows only as the exception. TD-264 rule 7 needs a writer that retitles, and TD-264's own title has to be retitled.
- An answered `**Ask:**` cannot be removed, so TD-261's answered Ask had to be rewritten as "Answered: yes" instead of dropped.

Asked for by ShiftLead's grinder (ao-shiftlead-grinder-ao-2, by `ask`, 2026-11-14, m-1a30e0c9140b).

**Location:** files/scripts/ledger.py (edit() ~1219, the set and edit flags); files/scripts/ledgerboard/ledger.py (set --title, edit --remove; vendored v2.8); tests/; files/docs/cadence.md §2.12; files/docs/cadence-changes.md

**Fix:** In `files/scripts/ledger.py`'s `set`/`note`/`edit` front end, pass the v2.8 forms through to ledgerboard's writer:
- `set --title T`. It is valid with or without other fields, so "give at least one field to set" counts a title. It is refused alongside `--by`, since a lift is not a retitle.
- `edit --section NAME --remove`, which takes the place of `--from`, exactly one of the two. The "never emptied" error stays for an empty `--from` and names `--remove`.

Better still, build `set`'s and `edit`'s flags from the vendored module's own parser, as `board_edit.py` passes `add` through, so the next ledgerboard flag needs no change here. Add cases to the ledger writer's tests: a retitle, a removal, a refused `--remove` with `--from`, and an archived entry refused. Add a `files/docs/cadence-changes.md` entry, and update cadence.md §2.12 where it lists the writer's verbs.

**Done when:** `ledger.py set TD-n --title "…"` retitles an open entry through ledgerboard's writer, and `ledger.py edit TD-n --section Ask --remove` removes that section. Both are tested, with the refusals. cadence-changes.md records them.
