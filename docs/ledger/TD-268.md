**Priority:** high
**Type:** feature

**Status:** Open

**Why:** Paul switches between projects all day, and what sessions write to him is often shorthand he cannot follow cold. ShiftLead's TD-1845 design (its design §4.10 *Text a person reads is checked at its writer*, ShiftLead PR #3882) makes the rules for that text one check, written once in ledgerboard and run by every writer: ShiftLead's own mail, and this repo's board and ledger writers, which ShiftLead's sessions also run. Until this repo's writers call it, a board line or a ledger Ask that breaks the rules still reaches him, and ShiftLead's own refusal (its TD-1846) is gated on this check reaching the ledgerboard vendored here.

This replaces the home-grown check TD-264 planned for its rules 1–3 and 7. The design keeps Paul's rules but moves one: TD-264's rule 3 (the context opens with the repo and the larger work) is replaced by *where it is is drawn, not written* (Paul, 2026-11-14, ShiftLead m-2996b23628a7) — the Queue card's head shows the entry, so no text repeats it, and the title rule takes rule 3's number.

**Fix:** Call ledgerboard's checks — `person_text_problems`, `title_problems` and `sentence_problems`, built by ledgerboard's TD-118 for its TD-111 design (plan `docs/plans/TD-111-person-text.md` in ShiftLead/ledgerboard, D1, D2, D4) — from this repo's command-line writers. Each returns a list of `PersonTextProblem(rule, refuse, line)`; rules 1–3 refuse and list every problem at once, rule 4 warns. `people` is the board's `People:` names.

The vocabulary is ours, not the package's (the plan's D1). The package exports only `ACTOR_WORDS` (plain-English pronouns), `SENTENCE_WORDS` and `CODE_EXTS` — no `ACTOR_NOUNS` or `COINED_TERMS`. Every call passes the process's words: `actors=` (the role nouns *session, seat, techlead, grinder, designer, manager, director, reviewer, builder, lead, worker, agent* and the phrases *the home*, *the host agent*), and on `title_problems` `coined=` (*slice, seam, tripwire*) and `labels=` (the patterns `[A-Z]{1,2}\d+` for a build, finding or round id, and `#\d+` for a PR number). Without `actors=` the check refuses a right answer (*a session pins it*). Keep the vocabulary as one data file in the payload, read by every writer here, so ShiftLead's `msg` road (its TD-1846), which runs from its agent-cadence pin and cannot import this repo's code, can read the same file rather than a copy that drifts; the builder tells ShiftLead's question seat the file's path when it merges. Where ShiftLead settles on another home for it, follow that.

- **`board_edit.py add --kind decide`**: a bold opening, when the text has one, is the whole question and ends in `?`; today's shape `**Title** — question?` is refused, and so is a bold run mid-text. With no bold opening the text the writer hands `item_file()` is read whole as the sentence. The `--answer` list is rule 2 (an answer the package reads as a form, `Hold: <note>`, by its consequence alone), the detail block's context, caveats, recommended and otherwise text rule 4 (a warning). The line's `Context:` field is never read as rule 4's context, since it names a gate.
- **`board_edit.py add --kind act`**: opens with its task in bold (refused without one, a writer's message), checked as rule 1; its tail and the detail block's context are rule 4 (a warning).
- **`ledger.py`**, on every path that writes an Ask or Answers (`new`, `edit --section Ask` or `Answers`): the Ask's first paragraph is the sentence, a question of one sentence ending in `?`, and its later paragraphs the context; each answer is rule 2. Most Asks written today (*Say Go to file the one build, One more round, or Hold with a note*) are statements and are refused: the cure is the question first, then a blank line, then the rest.
- **`ledger.py new`**, and the retitle path `set --title`, check the title with `title_problems`; never `renumber`, archive or reopen. A board line is held to rule 1, not to `title_problems`, which narrows TD-264 rule 7's *and so does a board item's line*.
- The check runs in this repo's command-line paths only. ledgerboard's own writers and its command lines (`plan_add`, `plan_new`, `plan_edit`, `python3 -m ledgerboard.board|ledger`) never call it (the plan's D3), since the gate sweep and a person's *Put on the board* write through them.

First vendor the ledgerboard release that carries the checks (`vendor_ledgerboard.sh`, as TD-263 did): the next minor after v3.1, v3.2 unless something takes it first. TD-118's builder tells this repo's techlead which release carries it on its merge; TD-272 vendors v3.1 first.

The cadence's text:
- `files/docs/cadence.md` §3.3 and §3.5 for a board line (a `decide`'s bold opening is its whole question, an `act` opens with its task in bold), and §2.3's entry shape for a title, an Ask (a one-sentence question first, context in a later paragraph) and Answers, each stating the rules.
- Every Ask this repo teaches is rewritten as a question first: the end-of-rounds item's and a `Hold` note's Ask (§4.8), the gate's (§2.4, §2.14), and this repo's briefs in `docs/briefs/` where they write to the person. ShiftLead's own stage briefs are ShiftLead's (its TD-1848). The answers carry their actors: a gate's *Yes — a session lifts the gate and the entry can be picked | Not yet — nobody picks the entry until you say*, and the end-of-rounds item's *Go — the grinders build it | One more round — a session runs one more review round, then asks again | Hold: <note> — a session revises the design as your note says*.
- A `files/docs/cadence-changes.md` entry, and tests: for each writer, a passing case and a refused one per rule, a warned rule 4, a `decide` with a bold run mid-text, an Ask of statements, and a right answer naming *a session* that passes only because `actors=` is given.
