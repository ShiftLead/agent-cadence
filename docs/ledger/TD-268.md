## TD-268: The board and ledger writers here refuse text a person cannot follow, using ledgerboard's shared check

**Priority:** high
**Type:** feature

**Status:** Open

**Why:** Paul switches between projects all day, and what sessions write to him is often shorthand he cannot follow cold. ShiftLead's TD-1845 design (its design §4.10 *Text a person reads is checked at its writer*, ShiftLead PR #3882) makes the rules for that text one check, written once in ledgerboard and run by every writer: ShiftLead's own mail, and this repo's board and ledger writers, which ShiftLead's sessions also run. Until this repo's writers call it, a board line or a ledger Ask that breaks the rules still reaches him, and ShiftLead's own refusal (its TD-1846) is gated on this check reaching the ledgerboard vendored here.

This replaces the home-grown check TD-264 planned for its rules 1–3 and 7. The design keeps Paul's rules but moves one: TD-264's rule 3 (the context opens with the repo and the larger work) is replaced by *where it is is drawn, not written* (Paul, 2026-11-14, ShiftLead m-2996b23628a7) — the Queue card's head shows the entry, so no text repeats it, and the title rule takes rule 3's number.

**Location:** files/scripts/board_edit.py (add); files/scripts/ledger.py (new, edit --section Ask|Answers, set --title); files/scripts/ledgerboard/ (vendored); vendor_ledgerboard.sh; files/docs/cadence.md §2, §3.3, §3.5; docs/briefs/; files/docs/cadence-changes.md; tests/; ShiftLead docs/design/4.10-messages.md *Text a person reads is checked at its writer*

**Fix:** Call ledgerboard's three checks — `person_text_problems`, `title_problems` and `sentence_problems`, filed in ledgerboard as its own entry — from this repo's command-line writers. `person_text_problems` and `title_problems` each return a list of problems `(rule, refuse, line)`; `sentence_problems` is rule 1's word count and sentence end alone, the reader both they and ShiftLead's card use. Rules 1–3 refuse and list every problem at once, rule 4 warns. `people` is the board's `People:` names.

- **`board_edit.py add --kind decide`**: its bold head (else the line's first sentence) and the detail block's question are rule 1, its `--answer` list rule 2, the detail block's context and recommended rule 4 (a warning). The line's `Context:` field is never read as rule 4's context, since it names a gate.
- **`board_edit.py add --kind act`**: a bold head is required (refused without one) and checked as rule 1; the detail block's context is rule 4 (a warning).
- **`ledger.py`**, on every path that writes an Ask or Answers (`new`, `edit --section Ask` or `Answers`): the Ask is rule 1, each answer rule 2.
- **`ledger.py new`**, and any retitle path (TD-265's `set --title`), checks the title with `title_problems`; never `renumber`, archive or reopen. The title check is an entry's; a board line is held to rule 1, not to `title_problems` (the design's rule 3), which narrows TD-264 rule 7's *and so does a board item's line*.
- The check runs in the helpers' command-line paths only, never inside ledgerboard's `plan_add`, `item_line` or its ledger writers, which the gate sweep and a person's *Put on the board* also call.

First vendor the ledgerboard release that carries the checks (`vendor_ledgerboard.sh`, as TD-263 did).

The cadence's text:
- `files/docs/cadence.md` §3.3 and §3.5 for a board line, and §2's entry shape for a title, an Ask and Answers, each stating the rules.
- Where this repo teaches the person's answers, the convention answers with their actors: the gate's `decide` item (§2.4, §2.14) and the end-of-rounds item (§4.8), and this repo's briefs in `docs/briefs/` where they write to the person. ShiftLead's own stage briefs are ShiftLead's (its TD-1848). The answers: a gate's *Yes — a session lifts the gate and the entry can be picked | Not yet — nobody picks the entry until you say*, and the end-of-rounds item's *One more round — a session runs one more review round, then asks again | Go — the grinders build it | Hold: <note> — a session revises the design as your note says*.
- A `files/docs/cadence-changes.md` entry, and tests: for each writer, a passing case and a refused one per rule, and a warned rule 4.
