## TD-269: Remove the rename's machine-local stopgaps: the dev-cadence stub and stale-worktree-nudge

**Priority:** low
**Type:** debt
**Added:** 2026-11-14
**Status:** Open
**Id take:** 33656e5d314c48d58d137f1760e93317
**Related:** TD-194, TD-191, shiftlead#TD-1016

**Why:** The rename sitting (TD-194, plan `2026-10-29-hard-rename`) left two machine-local stopgaps in place of a hard delete, decided by Paul at step 9. `~/.local/bin/dev-cadence` is a stub: it runs nothing, names the new command and exits 2, so an old SessionStart line fails open. `~/.local/bin/stale-worktree-nudge` is a user-level SessionStart hook, run by one entry in `~/.claude/settings.json`, that tells a worktree branched before its repo's rename PR to merge main. Neither is tracked in any repo, so without an entry nothing says when they go, and the nudge then runs in every session for good.

**Location:** `~/.local/bin/dev-cadence`, `~/.local/bin/stale-worktree-nudge`, `~/.claude/settings.json` (its SessionStart entry for the nudge); the plan `docs/plans/2026-10-29-hard-rename.md` (*Outcome*, the step 9 stub)

**Fix:** Remove both once nothing on the machine still needs them:

- **The nudge** (the script and its `~/.claude/settings.json` SessionStart entry): once no worktree outside `~/dev-cadence` carries the old SessionStart line (`dev-cadence hook session-start` in its `.claude/settings.json`). On 2026-11-14 four did, all clean and with nothing ahead of their main: `agent-cadence` `ac-proofread`, `samscrape` `grinder-sam-1` and `grinder-sam-2`, and `shiftlead` `prompts`. Merging main into each, or reaping it (`reap_worktrees.sh`), clears it. The nudge is silent in `~/dev-cadence`, whose main still has the old table.
- **The stub:** once `~/dev-cadence` leaves the roster. Its SessionStart line is the only caller left (its git hook shims run its own `files/` and never the launcher). TD-191 keeps it on the roster until no `Blocked by` names `dev-cadence#`. On 2026-11-14 one did: ShiftLead TD-1016. Removing the stub earlier only turns that line's message into *command not found*.

Done when both files are gone from `~/.local/bin`, the settings entry is gone, and a session in each roster repo starts with no error.
