## TD-275: The cadence check accepts a board item added and closed within the same pull request

**Priority:** medium
**Type:** debt
**Added:** 2026-11-14 (ShiftLead's designer ao-shiftlead-designer-ao-1, through an ask; drafted by ao-agent-cadence-ac-techlead)
**Status:** Open
**Id take:** 63be9a6b9e364defbc66c364a8fff3d2

**Why:** A PR whose own commits add a board item and then close it with `board_edit.py done` fails the cadence check's `board` row, although every write was the helper's. The row judges the board's net change, the merge-base (open PR) or the merge commit's parent (merged PR) against the head, items paired by id (`row_board()`, `board_change_problems()`). The item is not at the base, so the head's closed file meets the branch for a new item, and a new item that is closed fails: "a closed item with no open item it closes — board_edit.py done". The writers' own sequence is refused by the rule that says to use them, and the only way through is to hide the history (squash the add and the close into an edit) or skip the item.

It happens in practice when an item filed early in a PR is reworded later in the same PR: an end-of-rounds decide item was added, then closed and written again after the closing fact-check reworded its caveat, on ShiftLead/shiftlead#3929 (2026-11-15). That repo's pin predates TD-263, so it showed there as the v2 board's archive-net message ("the archive gained …, which is not a line the board lost"). Checked against origin/main on 2026-11-14: the v3 board row has the same gap under the message quoted above.

Asked for by ShiftLead's designer (ao-shiftlead-designer-ao-1, by `ask`, 2026-11-15, m-6f01ff2bb382).

**Location:** files/scripts/check_cadence.py (board_change_problems() ~line 1886, its new-item branch ~line 1936; row_board() ~line 2097); files/docs/cadence.md §3.4; tests/

**Fix:** Pick one, and say which in the PR:

1. **Accept an add-and-close inside the change** (the asker's first suggestion, preferred): in `board_change_problems()`, a closed item absent from the base passes when its open form, the closed file with the close's fields taken off, is one `board_edit.py add` would write (the new-item checks: `item_file_problem()`, the gate's `board_problems()`, a decide's detail block) and `writers_made(open form, closed file)` holds, at the path the writers put it. It needs no commit walk, so the open and merged readings stay the same rule.
2. **Or teach the procedure instead**: an item added in the same PR is reworded in place (`board_edit.py` the field's command, or `fmt`), never closed and added again, and the failure message names that. This leaves the writers' own sequence refused, so take it only if (1) admits a write no writer makes.

Either way, a test in `tests/` for the add-then-close PR, open and merged, and a negative case: a closed file new at the head whose open form no writer would write still fails. A `files/docs/cadence-changes.md` line if (2) changes what a session does.

**Done when:** A PR whose commits add a board item and then close it through `board_edit.py` passes the `board` row, open and merged (or, by the second Fix, the row's message and the procedure say to reword such an item in place), and a test pins it with its negative case.
