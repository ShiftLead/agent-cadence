## TD-277: The board can be split when its old archive first needs a cleanup the cadence check cannot read

**Priority:** medium
**Type:** debt
**Added:** 2026-11-15 (ShiftLead's grinder ao-shiftlead-grinder-ao-1, through an ask; drafted by ao-agent-cadence-ac-techlead)
**Status:** Open
**Id take:** 86d6d7cf7cab4fc2b0bc822030210a43

**Why:** A consumer whose v2 board does not split as it stands has no pull request the cadence check's `board` row passes, so the board cannot reach v3 at all. ledgerboard's `split_board()` refuses an archive line closed with no readable `Closed:` date ("date it first") and two lines of one kind sharing an id (TD-098 F62: keep one). No v2 writer dates a close or drops a copy, so the cleanup is a hand edit, and every road through the row is shut:

- a cleanup-only PR leaves a v2 board at its head, which an open PR fails ("split it first", `row_board()`); under older pins it failed as "the archive's existing lines changed";
- the cleanup carried inside the split PR reads `unknown` ("the v2 board at <base> does not split"), because the row splits the merge-base (`_as_v3()`), and the base is the board before the cleanup.

Seen on ShiftLead/shiftlead: its v2 archive at main 825b135 holds 71 closed lines with no readable `Closed:` date and 3 duplicate-id copies; its split PR #3968 (cleanup commit bc7fadec7, then the split 1d3aaac67) reads `unknown`. It blocks shiftlead TD-1881, ledgerboard's one-day rollout step due at the end of 2026-11-15 UTC. Checked against origin/main 0680fb4 on 2026-11-15: `row_board()` returns `unknown` when `_as_v3()` of the base is None, and `fail` for an open PR whose head is a v2 file.

Asked for by ShiftLead's grinder (ao-shiftlead-grinder-ao-1, by `ask`, 2026-11-15, m-6d48b7f80fb3).

**Location:** files/scripts/check_cadence.py (row_board(), _as_v3(), board_change_problems()); files/docs/cadence.md §3.3, §3.4; files/docs/cadence-changes.md; tests/

**Fix:** 1. (Recommended, in this repo; the road ledgerboard's migration watch, ao-led-tds-ledger, suggested on 2026-11-15, m-1210ba6c7f8d.) A **pre-split cleanup PR** passes the `board` row: its only board change is to the v2 stub and archive, `split_board()` refuses its base and accepts its head, and base→head changes nothing but (a) a `Closed:` date added to a closed line that had none and (b) a closed twin line dropped, which must be an exact copy of a line kept. The date is checked, not trusted: it must be the day of the commit that closed the line (`git log -S` on the line), so no close is dated falsely. Anything else fails, named. Since the base→head pair is the whole PR, the road is the same open (merge-base→head) and squash-merged (parent→merge commit), so no intermediate commit is needed. The split itself is then an ordinary split PR on a base that splits, which passes today. ledgerboard needs no change: the refusal and its cure are as its SPEC's *Migration* says. Document it in cadence.md §3.3 (the split) and §3.4 (the board row), with a cadence-changes entry.
2. (Alternative, upstream.) A v2 writer verb in ledgerboard that dates and dedupes the archive, which the row replays like any writer's edit: a ledgerboard release and a vendor step here, too slow for the rollout date.

**Done when:** A PR that only dates closed v2 archive lines (each with its closing commit's day) and drops exact closed twins, on a base `split_board()` refuses and a head it accepts, passes the `board` row, open and merged; tests pin the pass and its negative cases (a wrong date, a twin that is not an exact copy, any other change).
