## TD-278: The Grok Build backend's leader, open-session list and per-profile homes are unread on a live interactive session

**Priority:** Low
**Type:** debt
**Added:** 2026-11-15
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** dd18e999c8374296ac679e70782f1024
**Blocked by:** until 2026-11-29

**Why:** TD-252's Grok Build backend (PR #227) was built on facts read off grok 1.0.77 with no interactive session running: a `grok agent stdio` under a scratch `GROK_HOME` showed the process shape, and the user guide and an old session showed the layout. Three things it guards against were not seen live, so the backend errs toward *cannot see* on each. (1) Whether an ordinary TUI session starts a `grok agent leader` (the daemon route). If it does, every Grok use reads as *cannot see grok* while the leader runs, which is honest but noisy enough that people learn to ignore it. (2) What a row of `~/.grok/active_sessions.json` holds. It was `[]`, so the backend treats any non-empty content, with no grok process found, as blind. Its rows may name the session id and cwd, which would give a live session its real id instead of `grok:<pid>`. (3) ShiftLead launches each Grok profile with its own `GROK_HOME`, so that profile's transcripts are outside `${GROK_HOME:-~/.grok}` and not indexed. Liveness comes from `/proc` and is unaffected.

**Location:** files/scripts/agent_sessions.py (the Grok Build backend); tests/test_agent_sessions.sh section 11

**Fix:** With a real interactive Grok session running in a scratch directory (one the person or a ShiftLead Grok profile starts), read: its process tree (`/proc/<pid>/comm`, `cmdline`, `cwd`, and any `agent leader` process with its cwd), `active_sessions.json` while it is open, and where the profile's `GROK_HOME` points. Then, in `files/scripts/agent_sessions.py`: read the live id and cwd from `active_sessions.json` if its rows carry them; narrow the leader blind line if a leader always accompanies a visible client; and read each live grok process's `GROK_HOME` from `/proc/<pid>/environ` for its transcripts, if profiles keep their own. Update the backend's *as read* comment and tests.

**Done when:** The backend's comment states each fact as read on a live interactive session, and each of the three rules is either kept with that evidence or changed, with a test.
