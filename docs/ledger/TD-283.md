## TD-283: This repo's ledger cannot be moved to ledgerboard's stricter entry text until it takes the release that flags and migrates it

**Priority:** medium
**Type:** feature
**Added:** 2026-11-16 (ledgerboard's designer ao-ledgerboard-lb-designer, through an ask; drafted by ao-agent-cadence-ac-techlead)
**Status:** Open
**Id take:** 688129286c544932bde1b13d9869739d
**Blocked by:** event (ledgerboard-body-release)

**Why:** ledgerboard's next minor release (its TD-133, filed by ShiftLead/ledgerboard#402, still open on 2026-11-16; the first of TD-124's two releases; plan `docs/plans/TD-124-body-grammar.md` in ShiftLead/ledgerboard, D7, Paul's choice of two steps on 2026-11-16) gives `check()` four flags on an entry's body: `lead-form`, `glued-lead`, `fence-open` and `field-lines`. Its writer refuses an edit that makes one, and it adds a `migrate-body` that rewrites a ledger, open and archived entries alike, so that none is flagged. The major release after it reads a body strictly, and a ledger not migrated by then reads wrong.

This repo reaches ledgerboard only through its vendored copy (`files/scripts/ledgerboard/`, `vendor_ledgerboard.sh`) and the `ledger.py` wrapper, and code here never calls ledgerboard's writers directly (cadence.md §2.12). So until this repo vendors the minor, passes `migrate-body` through `ledger.py` and runs it on its own ledger, no consumer pinned to agent-cadence can migrate before the major arrives.

Asked for by ledgerboard's designer (ao-ledgerboard-lb-designer, by `ask`, 2026-11-17, m-61bb27fb9805).

**Event (ledgerboard-body-release):** ledgerboard has tagged the minor release that carries TD-133's body flags (expected v3.3); this entry then vendors it.
check: file-contains ShiftLead/ledgerboard@v3.3 ledgerboard/__init__.py "glued-lead"

**Location:** files/scripts/ledgerboard/ (vendored); vendor_ledgerboard.sh; files/scripts/ledger.py; files/docs/cadence.md §2.12; files/docs/cadence-changes.md; tests/; ShiftLead/ledgerboard docs/plans/TD-124-body-grammar.md D6, D7

**Fix:** Once the gate lifts:

1. Vendor the release (`vendor_ledgerboard.sh`), with the four flags read by `ledger.py --check` and the cadence check's `ledger` row as ledgerboard's other flags are.
2. Add `ledger.py migrate-body`, a pass-through to ledgerboard's, with a fixture test (an open and an archived entry each carrying a non-strict lead, rewritten to the strict `**Name:**` form; a second run changes nothing).
3. Run it on this repo's own ledger as its own PR, so `--check` shows none of the four flags here.
4. cadence.md §2.12 names `migrate-body` and says it must run before a repo takes the major; `files/docs/cadence-changes.md` gets the line.

If the release ships under another tag than v3.3, re-point the event's check line (as TD-272 did).

**Done when:** The vendored ledgerboard carries the four body flags; `ledger.py migrate-body` exists with a test; this repo's ledger, archive included, has been migrated and `ledger.py --check` shows none of the four flags; cadence.md §2.12 and cadence-changes.md say to migrate before the major.
