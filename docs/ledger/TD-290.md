## TD-290: A far-reaching build waits for the person at merge when its design's go was not theirs

**Priority:** Medium
**Type:** feature
**Added:** 2026-11-17
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 9fa3142ac5c64b27b77845d7e951a399
**Blocked by:** TD-288
**Part of:** TD-281

**Why:** TD-281's design (`docs/plans/2026-11-17-design-round-endings.md`, rule 7) moved the merge-time backstop out to its own entry (Paul, 2026-11-17): a cadence-check row that holds a far-reaching build for the person at merge, when its design's Go was not theirs. The judge matches paths before the Go; this row is the check after the fact, on each build's PR.

**Location:** files/scripts/check_cadence.py; tests/

**Fix:** A `reach` row in `check_cadence.py`, structural like `person`, carrying what TD-281's rounds found about it:
- the `[far-reaching]` globs read from the base tree, never the PR;
- builds in the same repo only, since `Part of:` never names another repo (§2.4);
- the person read from the board's `People:` line, and a stated result with no board or no such line;
- a record with no `Reach:` line predates TD-281 and is not checked by this row (unlike `--verdict`, which reads it as far-reaching);
- an open PR fails when it changes a far-reaching path and its design's `Go by:` is not a person's; merged, a pass with a ⚠, as `row_person` does.

**Done when:** The `reach` row fails an open build PR that changes a far-reaching path under a design whose Go was not the person's, with tests for each state above.
