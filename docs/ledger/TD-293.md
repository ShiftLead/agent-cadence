## TD-293: The review counter misreads a findings table with an extra column, so a design can count Go with build-changing findings unread

**Priority:** medium
**Type:** debt
**Added:** 2026-11-18 (asked for by ShiftLead's designer session ao-shiftlead-designer-ao-1; drafted by ao-agent-cadence-ac-techlead)
**Owner:** grinder
**Status:** Open
**Id take:** ef91946e8ffe4395b34ecaf8cf420e07

**Why:** `review_stats.py` reads a review record's findings table by position, as seven columns: `id | round | by | topic | finding | class | status`, with `c[5]` the class and `c[6]` the status (`read_record`, the `table_rows(text, "id")` loop). `adr-template.md`'s closing comment draws that seven-column table, and this repo's four records use it. But cadence.md §4.8's prose lists the columns as *id, round, by, topic, the mechanism it touches in a phrase, finding, class, and a status*, which reads as eight, and a writer who follows the prose writes an eight-column table.

The reader takes any row of seven or more cells and never checks the header, so an eight-column record is misread without a refusal: `c[5]` is the finding's text, every class reads *unknown (read as unlabelled)*, and `--verdict` counts no build-changing finding. A design can then count `Go` with build-changing findings unread, and the judge and the person are shown a verdict the record does not support.

Seen 2026-11-19 in ShiftLead: its `docs/reviews/TD-1911.md` (before its commit 3c28c8858) and eight others (TD-1895, 1899, 1900, 1910, 1919, 1921, 1926, 1953) are in the eight-column form. Asked for by ShiftLead's designer session ao-shiftlead-designer-ao-1 (an ask to this seat, 2026-11-19, m-82ee46af425f).

**Location:** files/scripts/review_stats.py (read_record, the findings-table loop); files/docs/cadence.md §4.8 (the findings table's columns); files/docs/adr-template.md (closing comment); tests/test_review_stats.sh; files/docs/cadence-changes.md

**Fix:** 1. `review_stats.py` reads the findings table's columns by the header's names (id, round, by, topic, finding, class, status), so an extra column such as a separate mechanism is ignored, and a header that lacks `class` or `status` is a problem reported for that record, never a silent misread. The Reviews table can be read the same way while the reader is open.
2. cadence.md §4.8's column list is reworded so it names the seven columns the template draws (the topic *being* the mechanism in a phrase), with a `files/docs/cadence-changes.md` line saying an eight-column record is read by its header.
3. A test with a record in each width (seven, and eight with a mechanism column) pins that both count the same classes and verdict.

**Done when:** A findings table with an extra column counts the same classes and verdict as the seven-column one, a table missing a needed column is reported, and §4.8's prose and the template name the same columns.
