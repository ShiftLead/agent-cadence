## TD-296: The temp-dir reaper misses where the inodes actually go: Claude Code session folders and shiftlead seats' test run folders

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-19
**Kind:** build
**Status:** Open
**Id take:** da06ad9d808444c5bb5a0885cb3e4f19

**Why:** On 2026-11-20 (UTC) one machine's /tmp, a tmpfs with 1,048,576 inodes, reached 0 free inodes, and no Claude Code session on the machine could start a command. TD-223's reaper was working and still had almost nothing it was allowed to remove: run five times after a 108k-inode stale pytest dir was cleared by hand, it reaped 315 entries. The inodes were in two shapes its patterns do not match:

- **Claude Code session folders**, `/tmp/claude-1000/<project>/<session-uuid>/` (scratchpads and command output files). 3,620 existed; 3,124 had nothing written anywhere in their tree for 3+ days and held 351,073 inodes. Removing exactly those, at the person's go, took /tmp from 86% to 52% of its inodes. The largest were grinder and designer seats' scratchpads at 11k–34k inodes each.
- **shiftlead seat temp dirs**, `/tmp/shiftlead-1000/<seat>/pytest-of-<user>/pytest-*`: about 300k inodes (one run dir 115k). The reaper's `pytest-*` rule looks only at `<tmp>/pytest-of-<user>/`, one level up. shiftlead's own test-suite fix is filed separately in shiftlead (`ao td add`, 2026-11-20); this entry is the reaper's side.

Reported by one of the person's sessions in another repo on 2026-11-20; counts are from that day's /tmp.

**Location:** files/scripts/check_tmp.py (REAP_PATTERNS, the reap walk); tests/test_check_tmp.sh; files/docs/cadence.md §3.9

**Fix:** Add both shapes to `check_tmp.py`'s reap set under the existing rule (owned by the running user, nothing anywhere in the tree newer than the age, read-only dirs made writable first): Claude Code session folders two levels under `$CLAUDE_CODE_TMPDIR`-or-`/tmp`'s `claude-<uid>/`, with a longer age than REAP_AGE (3 days: a resumed session expects its scratchpad), and `pytest-*` under any `<tmp>/*-<uid>/<seat>/pytest-of-<user>/`. Name what each removed. Never touch `~/.claude/projects` (transcripts are kept for later analysis). REAP_BUDGET (2 s) already binds both `--hook` and `--report` (`main()` calls `reap()` for either mode past the threshold), and it is spent once listing (`reapable()`) and once removing (`reap()`), so a 350k-inode backlog clears over many runs; consider a larger budget for `--report`, which the person runs by hand (`largest()` already gets WALK_BUDGET, 10 s).

**Done when:** Past its threshold, `check_tmp.py` removes a Claude Code session folder untouched for 3 days and an aged shiftlead seat `pytest-*` run dir, leaves a session folder with a file written today, reports what it freed, and tests cover each (with a sentinel that must be removed, per the restraint-test rule).
