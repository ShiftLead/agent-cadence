## TD-297: The review check should recognise ShiftLead's tool-made question to the person

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-22 (ao-shiftlead-grinder-ao-2, by request from shiftlead TD-2048; drafted by ao-agent-cadence-ac-techlead)
**Owner:** grinder
**Kind:** build
**Status:** Open
**Id take:** 3ab9476d4fb34dcf920d0a737af3dcb5
**Blocked by:** shiftlead#TD-2048

**Why:** ShiftLead's home is gaining a tool-made pull request that asks the person about one entry (shiftlead design 4.9c *A move to the person is the entry's decision*, its TD-2048, PR 4358). It adds a decision gate to the entry, with its Ask, Context, Answers, Lifts and a Log mark, and files the one decide item the gate sweep would file, then squash-merges at once with no review. The cadence check's review row knows the board's own tool-made edits and the lift, and this is neither, so every such question would read as landed without review in the weekly audit. That noise would hide a real unreviewed merge. Unlike the lift, no person's press stands behind this write, so the carve-out's case is narrower: the change only holds an entry back and asks, and it must be proved to do nothing else. ShiftLead's TD-2051, the first build to land one live, waits for this.

**Location:** files/scripts/check_cadence.py (row_ledger_lift_pr, the review carve-outs); files/scripts/ledgerboard/ (subject and verdict, vendored); files/docs/cadence.md §4; shiftlead docs/design/4.9c-flows.md

**Fix:** Add a review-row carve-out for the subject `<tool>: ask <person> on TD-n (session n/a)`, judged the way `row_ledger_lift_pr` judges a lift: a verdict that recomputes the write over the PR's base and head trees, never the title alone. The subject and verdict belong in ledgerboard beside `LIFT_SUBJECT_RE` and `ledger_lift_verdict`, so this takes a ledgerboard release and a vendor bump first; `check_cadence.py` then gains the row and tags it with its own `carve_out` value, so `--since` lists it as a tool merge.

The verdict passes only one commit that changes one open entry's file and adds one board item. In the entry: `decision (<person>)` joined to Blocked by with every earlier gate kept, the entry holding no decision gate before, the Ask, Context, Answers and Lifts written, one Log line, and nothing else changed. On the board: exactly the decide item the sweep would file for that gate. Anything else under that title takes ordinary review, its row saying why. Read the writer as merged (shiftlead `sessionorc.board._ask_in_tree`), since it replaces an earlier Ask and Answers rather than keeping them. Record the carve-out in cadence.md §4 and `files/docs/cadence-changes.md`. It changes what the gate accepts in every repo, so its merge is Paul's (cadence.md §4.11 as the person's own layer sets it).

**Done when:** A pull request made by ShiftLead's ask writer passes the review row with its own carve-out and is listed as a tool merge by `check_cadence.py --since`. Tests show ordinary review for the same title on a PR that also changes another field, another entry or another board item, drops an existing gate, or adds a gate to an entry already waiting on a decision.
