**Why:** ShiftLead's home is gaining a tool-made pull request that asks the person about one entry (shiftlead design 4.9c *A move to the person is the entry's decision*, its TD-2048, PR 4358). It adds a decision gate to the entry, with its Ask, Context, Answers, Lifts and a Log mark, and files the one decide item the gate sweep would file, then squash-merges at once with no review. The cadence check's review row knows the board's own tool-made edits and the lift, and this is neither, so every such question would read as landed without review in the weekly audit. That noise would hide a real unreviewed merge. Unlike the lift, no person's press stands behind this write, so the carve-out's case is narrower: the change only holds an entry back and asks, and it must be proved to do nothing else. ShiftLead's design says the first build that lands one live waits for this carve-out; its TD-2051 is expected to be that build, though its ledger entry does not yet name this one.

The verdict passes only one commit that changes one open entry's file and adds one board item. In the entry: `decision (<person>)` joined to Blocked by with every earlier gate kept, the entry holding no decision gate before, the Ask, Context, Answers and Lifts written, two Log lines (the writer's `gate added` line and its `asked by the stage record` mark), and nothing else changed. On the board: exactly the decide item the sweep would file for that gate. Anything else under that title takes ordinary review, its row saying why. Read the writer as merged (shiftlead `sessionorc.board._ask_in_tree`), since it replaces an earlier Ask and Answers rather than keeping them.
