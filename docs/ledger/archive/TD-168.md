**Why:** until TD-129's closing slice (2026-10-28) the first `sync.sh` into a new repo did five things `adopt` does not: it read the repo's own ledger and board and stopped, writing nothing, on one that failed `ledger.py --check`, held what the readers would skip or declared a newer format major (TD-133); it added `.claude/worktrees/` (and the `worktree-root` setting's directory) to `.gitignore`; it merged the clone's `autoMemoryDirectory` into `.claude/settings.local.json`; and it warned on settings that lacked the SessionStart line or a `.gemini/settings.json` that did not name `AGENTS.md`. `adopt` says it does not do the per-clone steps, but a repo adopted now gets a ledger nothing checked, and a worktree directory git shows as untracked until someone reads the checklist.

**Fix:** give `adopt` the read-only checks first — the ledger and board check (refusing, nothing written) and the two warnings — then the `.gitignore` lines; the memory path last, since `hydrate_worktree.sh` already writes a worktree's. Each from the fixture's code, never a second copy of it beside the first.

**Done when** `dev-cadence adopt` on a repo whose ledger fails `--check` refuses with the list, and a new repo's `.gitignore` and memory path are set, each with a case in `tests/test_adopt.sh`.
