## TD-192: Once agent-cadence is public, decide whether CI runs on GitHub Actions again

**Priority:** low
**Type:** debt
**Added:** 2026-10-28 (session `dc-tds`, from the cut-over's round-4 review)
**Owner:** grinder
**Kind:** decision
**Status:** Resolved 2026-10-30 (Paul, session `td-191`: "option 1, fork PRs only"). `ci.yml` runs on `pull_request` with a job `if:` that skips a PR from this repo, and it keeps `workflow_dispatch`. It is not a required check. The other two options were turned down. Every PR as a required check would run the suite twice on every push and make ac-grind wait on Actions. Leaving it by hand would leave the first outside PR to be prechecked on the machine, running its code there. A run on this repo's own PRs, even one that is not required, would still gate them, because the `ci` row judges every check run when the base requires none (`check_cadence.py` `_judge_runs`). One cost is known: `check_cadence.py`'s `gating_events` and `head_workflows` read the trigger, not the job's `if:`. So until TD-207, every PR here shows the ⚠ *runs on every pull_request*. On a token without Checks permission the `ci` row would also read unknown (TD-156), but this machine's token has `repo` scope. CLAUDE.md and the briefs say a fork's PR is Paul's: he reads its diff and sees that run green before `precheck.py --pr` runs it on the machine. The same question for every consumer is agent-cadence#TD-207, for ShiftLead's own repo shiftlead#TD-1285, and for ledgerboard its TD-003.
**Location:** `.github/workflows/ci.yml` (`workflow_dispatch` only); `docs/cadence.toml` `precheck`; CLAUDE.md's *Known dogfooding gaps*

**Why:** TD-148 made the merge gate local because the account's Actions minutes are one shared pool. Public repos run Actions free, so that reason lapses once agent-cadence is public. A forge-run check would also gate outside contributors' PRs, where no local precheck runs. The publish gate is the exception: it needs the machine's `publish-names`, so it stays local.

**Fix:** decide whether `ci.yml` runs on `pull_request` (ruff and the suite, not the publish gate) as a required check beside `cadence/precheck`, and record it in this entry.

**Related:** TD-148, TD-191.
