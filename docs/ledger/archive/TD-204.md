**Why:** the 2026-10-30 dataset (`docs/review-data/`, 97 designs) was mined by hand from design histories, ADRs and transcripts, and it could answer how long review loops run but not whether they work: only one design (TD-173's ledger writer) recorded which findings were build-changing, tokens were recovered for under half the reviews, the models were named loosely, and the link from a design to the defects it later let through was guessed from ledger citations, a lower bound that missed most of what a careful re-read found. The trial (`trial-rev18.md`) had to use proxies for the labels and could not test the link at all. TD-203's findings table fixes the labels going forward; this entry adds the rest, so the data accumulates as a by-product and the caps can be tuned from evidence. As agents get stronger and tokens cheaper, the same data shows when late rounds start finding real problems again, which is when a repo should raise its caps.
