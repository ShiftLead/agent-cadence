## TD-205: A ledger that declares its own fields cannot carry `Taken by:`, so its new ids go unrecorded

**Priority:** low
**Type:** debt
**Added:** 2026-10-30 (TD-204's round-1 fact-check, R2; Paul: "Same release, own TD")
**Status:** Superseded 2026-10-30 by TD-188: `Id take` replaces `Taken by` as a cadence field in ledgerboard v2.2 (TD-188's design, decided 2026-10-28), so `taken by` does not join `CADENCE_FIELDS`; found while filing TD-204's builds (its record's F90; Paul: "Supersede by TD-188").
**Taken by:** 2d1e517b5515
**Location:** `files/scripts/ledgerboard.py` `CADENCE_FIELDS` (vendored; canonical ShiftLead/ledgerboard, its `SPEC.md`); `files/scripts/ledger_next_id.py:338` (`writable`); cadence.md §2.10, §2.12; the seed `files/docs/technical_debt.md` entry template; `tests/test_parity.sh`

**Why:** §2.10 has every new entry carry `**Taken by:**`, but `Taken by` is not one of ledgerboard's `CADENCE_FIELDS`, so a ledger with a `Fields:` line (ShiftLead's) flags it `undeclared-field`, an error under `--check --since`, and a `Fields:` line cannot declare a free-valued field. `ledger_next_id.py` works around it: `writable = "taken by" in LB.CADENCE_FIELDS or not declared(...)`, whose first half is always false today, so in such a ledger the provenance §2.10 asks for is never written. `Escaped from:` (TD-204) has the same problem and the same fix.

**Fix:** in the ledgerboard minor release TD-204 builds, add `taken by` to `CADENCE_FIELDS` and to `SPEC.md`'s spec fields; name it in §2.12's list and the seed template's header block (`tests/test_parity.sh` holds both to `CADENCE_FIELDS`); `ledger_next_id.py`'s `writable` then holds everywhere, and its check and the §2.10 text about such ledgers go.

**Done when** a ledger with a `Fields:` line takes `**Taken by:**` with no `undeclared-field`, and `ledger_next_id.py` asks for it there.

**Related:** TD-204 (the same release), ADR 2026-10-30 review outcomes.
