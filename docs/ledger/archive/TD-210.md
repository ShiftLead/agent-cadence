## TD-210: A precheck killed by SIGTERM strands its clean worktree: its cleanup is a finally, which a SIGTERM skips

**Priority:** low
**Type:** debt
**Added:** 2026-10-31
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-10-31: precheck.py turns SIGTERM/SIGHUP into an exit, so its finally removes the clean worktree; the three stale ones on this clone were reaped
**Taken by:** ao-agent-cadence-ac-grinder
**Location:** files/scripts/precheck.py main() (the tempfile/worktree try/finally ~277-294); tests/test_precheck.sh

**Why:** `precheck.py` removes its clean worktree in a `finally:` block (`files/scripts/precheck.py` ~291), and Python runs no `finally` on a SIGTERM: the default handler ends the process at once. So a precheck stopped by `timeout`, by a session stopping its background task, or by any other plain kill leaves `/tmp/precheck-<n>-…/head` registered in the clone's worktree list, a checkout of the PR's head nobody owns. On 2026-10-31 this clone held four: precheck-30, -31 and -49, and -56, which ac-grinder had just stopped (that one removed by hand). Each is a stranded worktree that the reaper and `git worktree list` readers must step around. Each also sits in a shared temp filesystem that check_tmp.py watches for running out.

**Resolved:** 2026-10-31 (PR #59) — files/scripts/precheck.py `_stopped`; tests/test_precheck.sh case 5c

**Done when:** A precheck stopped by SIGTERM leaves no worktree: `git worktree list` and `$TMPDIR` hold no `precheck-*` after the test kills one mid-run.
