**Location:** tests/test_p1_registry.sh (`TMP=$(mktemp -d)`, never removed); tests/test_p2_report.sh (`TMP=$(mktemp -d)`, never removed; its embedded Python's `tempfile.mkdtemp()` near the staleness_line case); tests/test_memory_guard.sh, tests/test_remote_tier.sh (an `rm -rf "$TMP"` at the end, no trap); files/docs/cadence.md §3.9 (*The shared temp filesystem*)

**Why:** Every session on a machine shares one /tmp, and when its inodes run out no session can start a command (TD-223's Why, seen 2026-10-26). The suite runs on every precheck and by hand before every PR, so a test that leaves its fixture behind adds to it each time. Checked 2026-11-04 on origin/main at a9a6ff2: a full `./run_tests.sh` under a fresh `TMPDIR` left three top-level directories. `test_p1_registry.sh` left one (`repo1`…`repo4`, `config`). `test_p2_report.sh` left two: its `TMP` (`delta`, `epsilon`, `zeta`, `origin.git`, …) and a Python `tmp*` holding `docs/cadence.toml` and `docs/user_attention.md`. `test_memory_guard.sh` and `test_remote_tier.sh` remove their `TMP` on a run that reaches the last line. A failure that aborts them, a `timeout`, or a stopped precheck leaves the fixture behind. shiftlead's grinder counted 154 top-level `tmp.*` in these shapes in this machine's /tmp that day (shiftlead#TD-1384). The request also named `tests/fixtures/legacy_sync.sh`, but that file makes no temp directory (its `mktemp -d` is inside an `echo`). The rest of the request, the precheck worktrees, is TD-223's.

**Resolved:** 2026-11-05 (PR #122)

**Done when:** A full `./run_tests.sh` under a fresh empty `TMPDIR` leaves it empty, and `test_memory_guard.sh` and `test_remote_tier.sh` leave nothing when killed partway through.
