## TD-241: The publish gate runs under xargs, so a split file list prints a clean last line after a failed batch and calls a needed accept line stale

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-06
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-06
**Id take:** c5aa490be08048f491f3cf4ea721aaab
**Location:** files/scripts/cadence_layer.py (--publish-check, --accept); docs/cadence.toml (precheck); files/docs/cadence.md §9.18

**Why:** A public repo's precheck runs the publish gate as `git ls-files -z | xargs -0 python3 …/cadence_layer.py --publish-check --accept <file>` (this repo's `docs/cadence.toml`, and cadence.md §9.18's recipe for a public repo). xargs splits a file list longer than its command-line limit into batches and runs the check once per batch. Each run prints its own `gate:` summary, so the output's last line can read clean while an earlier batch failed (xargs still exits 123, so the precheck's verdict is right). And each run judges `--accept` against its own batch alone, so an accept line matched in one batch is reported by another as *matched nothing — drop it if it is stale*: a false note that invites deleting a line the gate needs.

Scope: this repo's own precheck splits today. xargs fills a 128 KB command buffer (`xargs --show-limits`: *Size of command buffer we are actually using: 131072*; the 2 MB figure is only its ceiling), and `git ls-files -z | xargs -0 sh -c 'echo batch $#' _` ran 2017 files then 534 (2026-11-06). So the gate here already runs twice, and an accept line matched only in one half is called stale by the other — #164's precheck printed *accept line 74 … matched nothing — drop it if it is stale*, which may be such a note. Noted on TD-240 by Paul's session ao-led-tds-ledger (2026-11-06); the batch count was corrected by #165's Sonnet review.
