## TD-244: The merge gate runs the 12-minute precheck before the cadence check's cheap structural rows, so a fail found in seconds costs a precheck re-run, and the refusals do not all print their fix

**Location:** files/docs/procedures/cadence.md step 2; files/scripts/check_cadence.py (main's arguments; row_review, row_ledger, row_board, row_gates); files/scripts/precheck.py; files/docs/cadence.md §4.12

**Why:** The merge gate runs the slow check first and the cheap ones last. A PR then fails on a cheap check only after the slow one has finished. Fixing it moves the PR's head, so the slow check runs again. The procedure (`files/docs/procedures/cadence.md` step 2) runs `precheck.py --pr <n>` before `check_cadence.py`. ShiftLead's precheck takes about 12 minutes. The cadence check's structural rows (`ledger`'s canonical-form check, TD-201; `review`; `board`; `gates`) read only the diff and the PR's comments, and they answer in seconds. None of them can be run alone: `check_cadence.py` has no `--structural` mode, or any other way to choose rows.

Seen in a trial review of three ShiftLead seats' transcripts (designer-ao-1, grinder-ao-2, techlead-ao-1), 2026-11-03 to 2026-11-06, in 20+ PRs:
- An archived or edited entry not in canonical form (for example, Resolved below Location). The seat runs `ledger.py fmt` by hand, the head moves, and the precheck runs again: 6+ PRs (ShiftLead #2831, #2856, #2857, #2863, #2874, #2894).
- A review comment with no `cadence-review:` line: 3 PRs (#2805, #2820, #2851).
- A board commit the `board` row reads as not the writer's archive: 1.
- A new `decision (paul)` gate with no board item to answer it, which the `gates` row's `uncovered_decisions()` fails: 1 PR, which had 7 items filed by hand.

The harm: each case costs at least one more 12-minute precheck. Twenty-plus such runs in four days is the seats' time and the machine's. Each refusal also leaves the seat to work out the fix itself. For example, the `ledger` row names `ledger.py fmt TD-n`, but a review row that finds no line does not print the line it wants.

The canonical-form cases need checking before the Fix assumes their cause. `ledger.py archive` and `note`/`edit` write canonical form at this pin (cadence.md §2.12). So either the seats edited by hand, or ShiftLead's pin predates the writer that does. The Fix should say which.

**Resolved:** 2026-11-07 (PR #174)

**Done when:** A PR whose only fault is structural (a ledger entry not in canonical form, no review line, an uncovered gate) is refused before its precheck runs, and the refusal names the command or line that fixes it. The procedure runs the structural check first. The source of the six non-canonical entries is named in this entry's Log.
