## TD-260: A person's button answer, and the person's own interactive session, can't lift their decision gate (ShiftLead TD-1796)

**Priority:** high
**Type:** feature
**Added:** 2026-11-14 (Paul's session ao-led-tds-ledger in ShiftLead/ledgerboard, through an ask, for ShiftLead TD-1796; drafted by ao-agent-cadence-ac-techlead)
**Status:** Resolved 2026-11-14
**Id take:** 27a187522f94494b9d8b611ad3f751ee

**Why:** Paul cannot lift his own `decision (paul)` gate by pressing a button, and his own interactive session cannot lift it either. Today only a command he types by hand works. Paul's rule (2026-11-14, relayed by his session ao-led-tds-ledger): *"Lifts should be allowed by button press and in an interactive session. Button presses should always count as being done by the user."*

What happened on ShiftLead's TD-1796 (as the asker reported it, 2026-11-14):
- Paul answered *Lift it* from the Queue, on a seat's ask. The unattended session that applied the answer (grinder-ao-2) ran `ledger.py set … --by Paul`, then `--override`, and both were refused. `_set_lift` calls `agent_sessions.person_session_refusal()` before either route, and that refuses any session `ao` lists as unattended, seated or controlled.
- His own interactive Claude Code session then ran `ledger.py set TD-1796 --blocked-by "" --by Paul --answer Works`. ledger.py would have allowed it, since `person_session_refusal()` passes a `by_person`, attended session with no seat or controllers. Claude Code's auto-mode safety check refused the command before it ran.
- Only Paul typing the command himself worked (ShiftLead #3818).

So the guard TD-218 built to keep an unattended session from lifting a gate on its own also stops the session that carries out the person's recorded answer. Every lift Paul makes from the Queue then needs his hands at a terminal, which is the step the Queue exists to remove.

**Location:** files/scripts/agent_sessions.py (person_session_refusal ~955); files/scripts/ledger.py (_set_lift ~1393, its refusal ~1433); files/scripts/board_edit.py (decide ~572); files/scripts/check_cadence.py (gates row: lift_pr_verdict, tripwire); files/.claude/settings.json (the seed); files/docs/cadence.md (who lifts a gate); files/docs/cadence-changes.md; tests/test_ledger_set_lift.sh

**Resolved:** 2026-11-14 (PR #202)

**Done when:** An unattended session that holds a recorded answer from the person (a decided board item, or a person-inbox answer naming the gate) lifts that gate with `ledger.py set --by <person>`, and its Log line names the answer. Without such an answer it is still refused. Paul's interactive Claude Code session in auto mode runs the same lift without a refusal, through what the seed or procedure ships. `tests/test_ledger_set_lift.sh` has a case for each.
