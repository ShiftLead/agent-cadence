## TD-274: An item filed on another repo's board keeps the file paths in its words intact

**Priority:** medium
**Type:** debt
**Added:** 2026-11-14 (ShiftLead's grinder ao-shiftlead-grinder-ao-1, through an ask; drafted by ao-agent-cadence-ac-techlead)
**Status:** Resolved 2026-11-15
**Id take:** 53dfe77e8faa49cab85dfd766638c8ce

**Why:** When this repo files an item on another roster repo's board, it qualifies each bare `TD-n` in the item's words as `<this repo>#TD-n`, so that board does not read it as its own entry. The pattern, `(?<![#\w])TD-n\b`, also matches an id inside a file path, since `/` before it and `-` after it both pass: `docs/plans/TD-109-decision-missing.md` becomes `docs/plans/ledgerboard#TD-109-decision-missing.md`, a path that does not exist, in an item a person reads to act on. Checked 2026-11-14 against the pattern as written: a path id and `x/TD-109/y` are both rewritten.

The same idiom sits in two places: `gate_sweep.py`'s other-board writer (TD-229) and `ledger.py`'s notice writer (TD-226). ShiftLead fixed its own copy of the rule in ShiftLead/shiftlead#3935 (its TD-1868) with `(?<![#\w/.-])TD-n(?![\w/-]|\.\w)`: an id with `/`, `.` or `-` before it, or `-`, `/` or `.<word>` after it, stays as written, while a sentence ending `… TD-109.` is still qualified.

Asked for by ShiftLead's grinder (ao-shiftlead-grinder-ao-1, by `ask`, 2026-11-15T03:05Z, m-a8a506d07943).

**Location:** files/scripts/gate_sweep.py (the other-board writer, ~line 398); files/scripts/ledger.py (the notice writer, ~line 1746); tests/

**Resolved:** 2026-11-15 (PR #219)

**Done when:** Neither `gate_sweep.py` nor `ledger.py` rewrites a ledger id inside a file path when it qualifies an item for another repo's board, and a test for each pins the path and sentence cases.
