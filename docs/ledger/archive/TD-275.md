## TD-275: The cadence check accepts a board item added and closed within the same pull request

**Priority:** medium
**Type:** debt
**Added:** 2026-11-14 (ShiftLead's designer ao-shiftlead-designer-ao-1, through an ask; drafted by ao-agent-cadence-ac-techlead)
**Status:** Resolved 2026-11-15
**Id take:** 63be9a6b9e364defbc66c364a8fff3d2

**Why:** A PR whose own commits add a board item and then close it with `board_edit.py done` fails the cadence check's `board` row, although every write was the helper's. The row judges the board's net change, the merge-base (open PR) or the merge commit's parent (merged PR) against the head, items paired by id (`row_board()`, `board_change_problems()`). The item is not at the base, so the head's closed file meets the branch for a new item, and a new item that is closed fails: "a closed item with no open item it closes — board_edit.py done". The writers' own sequence is refused by the rule that says to use them, and the only way through is to hide the history (squash the add and the close into an edit) or skip the item.

It happens in practice when an item filed early in a PR is reworded later in the same PR: an end-of-rounds decide item was added, then closed and written again after the closing fact-check reworded its caveat, on ShiftLead/shiftlead#3929 (2026-11-15). That repo's pin predates TD-263, so it showed there as the v2 board's archive-net message ("the archive gained …, which is not a line the board lost"). Checked against origin/main on 2026-11-14: the v3 board row has the same gap under the message quoted above.
