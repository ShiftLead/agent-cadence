## TD-298: The merge line and its test leave a temporary directory behind on every run

**Priority:** Medium
**Type:** debt
**Added:** 2026-11-23 (ao-shiftlead-grinder-ao-2, by request from shiftlead TD-2128; drafted by ao-agent-cadence-ac-techlead)
**Owner:** grinder
**Kind:** build
**Status:** Resolved 2026-11-24
**Id take:** adccb8ef848e43adb336a60d7610ac6c

**Why:** Every merge made through the procedure's step 5 line leaves a temporary directory behind, in every repo on the cadence, because the line runs `m=$(mktemp -d)` and never removes it. The directory holds the gate, body, sha and subject files. Each is small, but the temp filesystem has already run out of inodes on this machine once (2026-10-26, recorded in the header of `check_tmp.py`), and an unattended team merges all day. `check_tmp.py` is the only cleanup, and it reaps these only once the filesystem is 80% used and the directory has been unchanged for a day. The line's test runs it whole with no TMPDIR of its own, so each `tests/test_procedure_merge.sh` run leaves 6 more directories outside the `$TMP` it cleans (re-measured on origin/main f661676, 2026-11-23: 6 directories; shiftlead's TD-2128 measured the same 6 across a full suite run).

**Location:** files/docs/procedures/cadence.md step 5; tests/test_procedure_merge.sh (run, its gh and glab shims); the line's copies in CLAUDE.md, docs/briefs/ and files/docs/cadence-rationale.md; files/docs/cadence-changes.md

**Resolved:** 2026-11-24 (PR #280)

**Done when:** A run of `tests/test_procedure_merge.sh` with its own empty TMPDIR leaves nothing in it. The test asserts, for both forms, that the line's directory is gone after a merge that succeeded and after one that failed, and that the line's exit status is the merge command's.

**Log:**
- 2026-11-24: archived: Resolved — Both forms of the step 5 line now remove their temporary directory and keep the merge command's exit status; the test asserts it for a merge that succeeded, one that failed and a refused gate.
